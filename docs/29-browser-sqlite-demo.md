# 한 PC 브라우저 SQLite 데모

D-43의 구현 기준선. 외부 DB 설정 없이 Vercel URL에서 한 PC·한 브라우저 탭으로 고객과 경영주를 번갈아 시연한다. 이번 문서는 설계이며 SQLite 앱·DB 자산·배포 검증을 완료했다는 뜻이 아니다.

## 확정 범위와 기술 선택

사용자 확정: Neon/Marketplace 없이 SQLite 사용, 한 PC의 브라우저 데모, 다중 사용자 충돌 검증 제외. 기술 기준선: sql.js WASM 단일 Worker/연결, 정적 초기 DB, IndexedDB에 SQLite 파일 사본 저장. IndexedDB는 업무 테이블을 별도로 관리하는 대체 DB가 아니라 새로고침 복원을 위한 바이트 저장 장소다.

- 거래·요청은 SQLite에서 SQL로 조회하고 트랜잭션으로 변경한다.
- 같은 탭의 역할 전환으로 고객·경영주가 같은 상태를 본다. 여러 탭/기기 동기화는 지원하지 않으며 시연 안내에 한 탭 사용을 적는다.
- SQL 서버·외부 DB 계정·상시 백엔드·분산 잠금·실제 인증·외부 푸시는 없다.
- 모의 결제, 동의, FIFO, MOQ 초과 접수, 보수적 자동발주, 픽업 48시간은 그대로 유지한다.
- SQLite 파일은 Vercel의 읽기 전용 초기 자산이다. 배포 서버의 /tmp나 함수 메모리에 거래를 쌓지 않는다.

## 자료 생성과 배포

1. goal 실행 당시 니즈·트렌드·상품·점포를 조사한다. 최종 seed는 서로 다른 상품 **200개 이상**, 실제 점포 8~12개, 합성 고객·경영주·모의 공급/가격/거래 시나리오를 포함한다.
2. JSON/CSV 등 출처 있는 정규화 입력과 SQLite 호환 SQL 마이그레이션을 저장소에 둔다. 로컬 builder가 SQLite 파일에 직접 삽입하고 무결성·고유 SKU·외래 키·필수 상태·수량을 검증한다. Python sqlite3를 사용할 수 있으나 최종 검사는 sql.js에서도 한다.
3. 같은 원본에서 `seed.sqlite`, 서버 검색용 `catalog.json`, schema/seed/catalog hash와 상품 수를 담은 manifest를 생성한다. 경로는 구현 시 고정한다. 날짜·조회 순서·난수 seed를 고정해 재현 가능하게 만든다.
4. 배포 빌드가 해당 입력으로 자산을 재생성·검증하거나 이미 검증한 산출물을 포함한다. 원본 없이 특정 PC에만 있는 DB 파일을 수동 복사해야 배포되는 구조는 피한다. 자산 생성 실패는 빌드 실패다.
5. 앱과 일치하는 WASM 파일을 같은 Vercel 배포에 포함한다. 서버 카탈로그와 클라이언트 manifest 불일치는 모델 제안 적용 전에 감지한다.

공개 자산에는 합성 시연 데이터와 공개 상품/점포 정보만 포함한다. 보호된 평가셋·정답·실제 사용자 데이터·비밀값은 포함하지 않는다. 이미지 원본은 DB BLOB에 넣지 않고 별도 자산 참조로 둔다.

## 시작·저장·복원

- **최초 실행:** 호환 사본이 없으면 정적 seed를 읽고 데모 세션을 초기화한다. 역할 전환만으로 seed를 재삽입하지 않는다.
- **명령:** 단일 서비스/Worker 큐에서 역할·세션·상태·동의·수량·예산을 검사하고 SQLite 트랜잭션을 실행한다. 화면 버튼 연타는 처리 중 비활성화하고 명령 ID를 저장해 같은 명령을 두 번 적용하지 않는다.
- **저장 성공:** 트랜잭션 반영 후 DB를 export하고 IndexedDB의 snapshot·schema/seed version·generation을 같은 저장 트랜잭션으로 교체한다. 저장 완료 후 성공 UI와 후속 이벤트를 공개한다.
- **저장 실패:** 성공으로 표시하거나 다음 발주/결제로 진행하지 않는다. 마지막 저장 성공 사본을 다시 열어 되돌리고 복구 안내를 제공한다. 첫 저장부터 불가능하면 읽기 안내·재시도/초기화 경로를 보이고 완전한 시연 준비로 판정하지 않는다.
- **새로고침:** 마지막 저장 성공 사본을 import하고 제약 설정과 schema/seed 호환성을 다시 확인한다. sql.js export/reopen 뒤 연결 설정이 유지된다고 가정하지 않으며 `PRAGMA foreign_keys=ON`을 연결마다 설정·검증한다.
- **버전 변경/손상:** 읽을 수 없는 snapshot을 조용히 덮어쓰지 않는다. ‘데모 데이터가 바뀌어 초기화가 필요합니다’ 안내와 재시작을 제공한다. 업무 중 자동 DB 업그레이드/운영 데이터 이전은 필수 범위가 아니다.
- **초기화:** 현재 데모 generation을 바꾸고 초기 seed로 복원·저장한다. 진행 중 모델 응답·저장 작업을 무효화하고 이전 요청을 새 세션에 적용하지 않는다.

명령 처리 중에는 모델을 기다리며 SQL 트랜잭션을 열어 두지 않는다. SQLite 변경→snapshot 저장→UI 반영은 한 명령의 완료 경계다. 같은 앱에서 reset 등 다음 변경은 그 경계를 지나서 처리한다. 이는 단일 탭 기본 동작이며 다중 클라이언트 충돌 해결 시스템이 아니다.

브라우저 데이터 삭제·시크릿 모드 종료·저장 공간 제한 이후 장기 보존은 보장하지 않는다. 시연 PC의 일반 브라우저에서 P07을 검증하고 초기화로 다시 시연할 수 있게 한다. 앱을 닫은 동안의 자동발주/푸시 실행은 없다.

## SQL와 서비스 계약

- UUID는 앱에서 생성한 TEXT, 금액·수량·UTC epoch milliseconds는 INTEGER, boolean은 0/1 CHECK, 구조화한 부가 값은 검증한 JSON TEXT를 기본으로 한다.
- PostgreSQL 전용 enum/jsonb/timestamptz/SELECT FOR UPDATE/pgvector/sequence 함수를 사용하지 않는다. SQL 제약과 쿼리는 실제 sql.js 빌드에서 검증한다.
- 접수 순서는 한 연결의 트랜잭션에서 할당하는 정수로 정한다. 금액·공급·예산 계산은 공통 도메인 함수가 수행한다.
- 로컬 역할·세션 검사는 일반 UI 오조작 방지이며 악의적 클라이언트를 막는 서버 보안이라는 주장을 하지 않는다.
- 서버는 정적 카탈로그를 검색하고 LLM 후보·경영주 변경안을 반환한다. 거래 변경 HTTP API·DB 연결 문자열은 만들지 않는다. 선택된 모델 출력은 브라우저의 최신 상태로 다시 검증한다.
- 시간은 공통 데모 clock으로 계산한다. 기기 날짜 변경 공격 방지는 제외하고 픽업 시작/마감 재설정 금지·48시간 경계는 유지한다.
- 자동발주는 단일 탭의 명시적 이벤트에서 실행한다. 정책 밖 제안은 경영주 확인이 필요하고 닫힌 브라우저를 대신하는 서버 스케줄러는 없다.

## 검색·자연어 품질

200개 이상 카탈로그의 별칭·토큰·속성 검색과 LLM 후보 구분이 기본이다. 문자열 근거와 SKU를 검증하고 자연어 품질 실험·holdout 보호를 유지한다. 벡터 실험은 별도 DB 없이 미리 생성한 embedding 파일과 소규모 벡터 연산으로 비교할 수 있으나 필수 아님. pgvector·새 플랫폼 가입을 되살리지 않는다.

## 완료 전 검증

| 단계 | 실제 검증 | 제외/한계 |
|---|---|---|
| P06 | 최소 실제 SQLite schema·insert/read·제약·rollback·export/import | 로컬 Python 성공만으로 브라우저 성공 아님 |
| P07 | Preview에서 WASM/seed 로드·쓰기·snapshot 저장·새로고침·역할 전환·reset | 외부 DB 접속 검사 없음 |
| G1 | 도메인 수량·예산·동의·FIFO·기한 함수 | 다중 사용자 부하/경합 제외 |
| G2 | 서비스 + sql.js 실제 SQL·rollback·중복 명령·snapshot 실패/복원·호환성 | 가짜 배열 저장소로 대체 금지 |
| G3 | 상품 식별→요청→묶음 발주→배정→결제→입고/수령의 상태·파일 사본 연결 | 서버 공동 DB를 요구하지 않음 |
| G4/G5 | 한 탭에서 두 역할 전환·새로고침·초기화·정상/예외, 별도 QA 담당의 독립 판정 | 서로 다른 프로필이 같은 DB를 공유한다고 가정하지 않음 |
| G6 | 정확한 Vercel 배포의 SQLite 자산/manifest·실제 모델·역할 전환·전체 흐름·reset | SQL 서버 보안·24시간 무인 운영의 검증 아님 |

같은 버튼 두 번·모델 timeout·잘못된 SKU·조건 변경·MOQ 초과 접수·미입고 수령 금지·동의 만료·48시간 경계·저장 실패는 남긴다. 동시 기기 예산 경쟁·분산 잠금·DB 서비스 계정/네트워크 시험은 제외한다. 실제 SQL 통합과 브라우저 저장 검증의 결과를 각각 기록한다.

## 근거와 이번 검토의 한계

2026-09-21 공식 문서 확인: [sql.js 파일 import/export·WASM](https://github.com/sql-js/sql.js), [Database API](https://sql.js.org/documentation/Database.html), [IndexedDB 저장소](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API), [Vercel 로컬 SQLite 제약](https://vercel.com/kb/guide/is-sqlite-supported-in-vercel). 브라우저 SQLite 선택은 이 계약을 이용한 기술 설계 판단이다. 아직 실제 의존성 설치·200개 데이터 생성·브라우저 앱 실행·배포는 하지 않았다.
