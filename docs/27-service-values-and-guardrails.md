# 서비스 가치와 불편을 늘리지 않는 규칙

D-37/43·CORE-25/26·AC-31/32의 최초 구현 기준. 고객의 말을 상품과 연결하고 경영주의 일을 줄이며, 충족하지 못한 니즈도 다음 판단의 근거로 남긴다. 이 문서는 구현·검증 계약이며 실제 사용자 효과를 측정한 결과는 아니다.

## 세 가지 가치와 이번 범위

| 가치 | 이번 필수 구현 | 부가 가치·범위 |
|---|---|---|
| 고객의 말이 상품코드와 연결됨 | seed DB의 실제 존재 SKU 확인, 모호함 구분, 미식별/미취급 니즈 정제·보존, 근거 있는 대체 후보와 원상품 구분 | 실제 GS 상품코드·재고와 연동했다는 뜻은 아님 |
| 경영주가 적은 수고로 공급 | 묶음 요약·자연어 수정, 사전 승인한 보수적 자동발주, 예외 위주 검토, 중복 승인/발주 방지 | 인근 점포 관심과 미취급 대체 상품 발주 **제안**은 선택 부가 기능. 합산 발주·자동 점포 이동은 제외 |
| 본부가 놓친 수요를 이해 | 원래 니즈·식별 결과·미충족 사유·대체 제시/선택·후속 구매 결과의 연결 기록 | 본부 화면·지도·CSV·자동 상품기획은 구현하지 않고 향후 가치로 설명 |

검색·추천 성공만으로 가치가 달성되지 않는다. 고객이 원치 않는 상품을 사거나 경영주의 승인 일이 늘어난다면 실패다. 추천 클릭, 실제 요청, 확보, 수령은 별도 사건이며 서로 대신 세지 않는다.

## 고객: 정확한 연결과 솔직한 실패

| 관측 | 안내·기록 | 금지 |
|---|---|---|
| 존재 SKU를 식별 | 이름·맛·용량을 고객이 확인 | 모델이 상품 ID 생성, 후보를 자동 구매 확정 |
| 식별이 모호함 | 후보 차이를 보여주고 제한된 추가 확인 | 같은 질문 무한 반복, 첫 후보 강제 선택 |
| 검색에서 찾지 못함 | `식별하지 못함`과 추출한 단서 기록 | 검색 0건만으로 실제 미등록·생산 종료 단정 |
| 해당 점포 미취급 확인 | 카탈로그 존재와 점포 미취급을 구분하고 모의 조건 명시 | 누락된 조건 row를 미취급 증거로 취급 |
| 점포 재고 없음 | 재고와 발주·공급 가능 여부 각각 표시 | 재고 0을 발주 불가/공급 종료로 치환 |
| 공급 제한 확인 | 근거·관측 시각·사유·가능한 다음 행동 | LLM이 전국 품절·종료 사유 창작 |
| API/모델/DB 오류 | 입력 보존·재시도·현재 거래 상태 표시 | 오류를 미식별 니즈/품절로 집계하거나 저장 성공으로 표시 |

점포 미취급이어도 데모 공급 조건에서 발주 가능한 SKU인지 따로 확인한다. 거래 요청 접수 가능 여부는 취급 라벨만으로 결정하지 않는다. 판매가·공급 조건이 불명확하면 확인되지 않은 상태로 안내하고 자동 구매에 넣지 않는다.

대체 후보는 검증한 카탈로그 SKU만 제시하고 `찾으신 상품과 다른 대체 상품`임을 명시한다. 공통점과 차이(브랜드·맛·용량·가격 등)를 확인된 속성으로 설명한다. 명시적인 제외·필수 조건을 어기는 후보는 추천하지 않는다. 속성 근거가 없으면 조건 충족을 주장하지 않는다. 적합한 대안이 없으면 없다고 알리고 니즈 보존·재입력 경로를 제공한다. 모든 입력을 거절하는 방식으로 안전 점수만 높이지 않는다.

대체 후보 노출·선택만으로 원래 요청의 SKU·점포·수량·가격·접수 순서·동의·결제를 수정하지 않는다. 대체 상품을 실제 요청하려면 상품·수량·한 점포·가격을 다시 확인하고 새 동의를 받는다. 기존 요청의 유지/취소/전환은 O-02/O-04/O-05의 채택 정책으로 명시한다. 단순 추천에서 기존 요청을 취소하지 않으며 새 요청 전환에서 이중 수요·중복 발주를 방지한다. 원상품 니즈와 후속 대체 선택의 연결은 남기되 대체 선택을 원상품 식별 정답으로 채점하지 않는다.

## 경영주: 검토는 묶어서, 실행은 승인한 범위에서

- 유효 수요와 기존 발주 연결을 먼저 확인한다. 관심/검색/추천·미식별·타 점포 수요를 현재 점포의 확약 수량에 더하지 않는다.
- 상품별 묶음에서 고객별 요청 상세로 내려가 상품·수량·가격·동의·접수 순번·발주 연결·확보/배정/결제/예약/픽업 상태를 확인할 수 있어야 한다. 상품 집계와 고객 상세 합계가 다르면 발주 판단을 진행하지 않는다.
- 동일 묶음·버전은 한 번 검토하고 성공/실패/보류를 한 요약에 표시한다. 품목별 연속 모달이나 변화 없는 동일 알림을 반복하지 않는다. 예외의 이유·영향 금액·가능한 행동은 숨기지 않는다.
- 사전 승인된 자동발주 정책이 유효하면 매 건 다시 승인받지 않는다. 유효 요청·예산·수량·MOQ·공급·활성 발주 연결을 로컬 서비스의 SQLite 트랜잭션에서 재검사하고 정책 밖 항목만 보류한다. 모두 보류해 자동발주 성공 경로를 없애는 것도 실패다.
- 자연어의 `이번 묶음`은 이번 제안에만 적용한다. `앞으로도`는 지속 정책 변경안이며 별도 명확한 승인 전에는 저장하지 않는다. 경영주는 현재 정책을 확인하고 끌 수 있어야 한다.
- 묶음 작성 후 수요 취소·예산 변경·정책 비활성화가 있으면 실행 직전 최신 조건을 확인한다. 오래된 승인을 새 수량이나 새 상품에 재사용하지 않는다. 중복 실행·재시도에도 주문은 한 번만 생성한다.
- 의미가 바뀐 묶음의 재확인과 변화 없는 재알림을 구별한다. 묶음 주기·알림 재노출·예외 재검토 규칙은 관련 G0에서 ADR로 고정하고 시간/이벤트 주입으로 검증한다. 필수 예외를 영구히 숨기는 식으로 알림 수를 줄이지 않는다.

선택 부가 기능인 인근 점포·대체 상품 제안은 `참고 관심 신호` 카드에 출처 범위·기간·고유 요청 수·불확실성을 표시한다. 다른 고객의 원문이나 식별정보를 노출하지 않는다. 현재 점포의 유효 확약 수요가 없는 품목은 자동발주 대상이 아니다. 현재 고객 요청을 다른 SKU/점포로 옮기거나 범위 밖 사입을 실행하지 않는다. 이번 데모에서는 제안을 보거나 숨기는 것까지만 허용하고 기존 흐름의 품질이 부족하면 이 부가 기능부터 보류한다.

## 데이터: 미충족 니즈도 원인을 잃지 않게

07번의 논리 계약에 따라 원문(보호 범위 안), 정제 단서, 추출 근거/불확실성, 식별 결과, 확인된 점포 취급/재고/공급 상태, 관련 SKU·점포, 사유, 관측 시각, 추천 노출·선택·후속 요청 ID를 연결한다. 합성 시연 데이터와 조사 사실을 구분하고 모델이 추측한 속성을 사용자 확정 니즈로 승격하지 않는다.

재시도는 같은 사건을 중복 니즈로 세지 않는다. 사용자 선택/취소 같은 다른 사건은 이력으로 구별한다. 시스템 장애는 운영 오류로 분류하고 니즈 통계에서 제외한다. 구매 요청 수·고유 고객 수·요청 수량·추천 노출 수·수령 수를 각각 계산한다. 고객 본인/허용된 점포·세션만 조회하도록 기존 격리를 유지한다. 본부 가치는 이 자료의 미래 활용이며 실제 매출 증가·수요 예측 정확도를 입증했다고 말하지 않는다.

## 독립 검증과 출시 차단

| ID | 반례·검사 | 통과 기준 |
|---|---|---|
| VAL-01 | 정확명/오타/특징/모호/미식별 입력 | 존재 SKU·확인 필요·미식별의 허용 행동, 정상 검색 유지 |
| VAL-02 | 미취급/재고 0/공급 제한/조건 누락/timeout | 상태별 안내·분류 정확, 오류는 니즈 건수에 포함되지 않음 |
| VAL-03 | 대체 후보 노출·거절·선택·전환 | 거래 불변, 새 확인/동의, 원래 흐름 복귀, 중복 수요·발주 없음 |
| VAL-04 | 추천/니즈 기록·타 점포 관심·반복 클릭 | 확약 수량·예산·발주량 변화 없음, 사건 중복 없음 |
| VAL-05 | 동일 수요 묶음 반복 조회·상품→고객 상세·재검토·실패/보류 혼합 | 중복 알림/승인 요구 없음, 상품 합계와 고객별 성공·예외 요약이 일치하고 재검토 경로 제공 |
| VAL-06 | 자동발주 정상/예산 초과/MOQ/반복 명령/정책 해제 | 유효 정책 안 정상 실행, 경계 밖 실행 0건, 예산·수량·중복 불변 |
| VAL-07 | 타 점포·타 세션 조회/상품→고객 상세 권한/정제 니즈/재시도 | 범위 격리·허용된 합성 고객 식별자만 노출·확정/추정 분리·기록 정합성, 본부 화면 없음 |
| VAL-08 | 개선 전후 같은 난이도·같은 작업량 비교 | 아래 사전 정의한 편의성 기준과 기존 필수 AC 모두 충족 |

고객은 올바른 SKU 도달률, 불필요 질문 수, 요청 완료의 필수 조작 수, P50/P95 시간, 대체 상품 오인·거절 후 복귀를 측정한다. 경영주는 같은 수요 묶음의 승인 횟수·화면 이동·완료 시간·중복 알림 수, 자동발주 정상 성공률과 예외 노출률을 함께 측정한다. 시간은 도구/네트워크 대기 조건과 표본 수를 밝힌다. 에이전트 브라우저 QA는 실제 사람 사용성 조사라고 부르지 않는다.

비교 기준선은 기존 정확 검색/수동 건별 처리 등 재현 가능한 동등 업무로 고정한다. 성공률 최소치·소요 시간/조작 허용폭·질문 상한은 21/23번의 기준선 **측정 전** ADR와 두 독립 검토로 정한다. 결과를 보고 문턱을 낮추지 않는다. 입력 소재·prompt·모델·seed가 바뀌면 영향받은 회귀 검사를 갱신한다. 공개 예시와 holdout은 분리한다.

동의 없는 SKU/점포 변경·결제, 가짜 코드, 초과/중복 발주, 권한 침해, 확약 수량 오염은 허용 0건이다. 하나라도 발견하면 해당 기능 통합/출시를 차단한다. 기존 필수 경로 실패를 추천 평균 점수로 상쇄하지 않는다. 추가 개선 한도에 도달하면 23번에 따라 가장 좋은 **최소 기준 통과** 버전을 유지하며, 필수 조건 미달은 문서 기록만으로 면제하지 않는다.

## 구현 루프에 연결

D01/D03은 상태·니즈·추천 계약, D04A/D04B는 정상/모호/미취급/장애/대체 거절 seed, FS/FC는 상품 식별·대체 확인, FM은 묶음·예외·정책 실행을 맡는다. N01~N03은 분류/추천과 불필요 질문 회귀, U01/U02와 Q01/Q02는 두 역할 편의성과 실패 회복, G5/G6는 정확한 후보/배포에서 AC-31을 확인한다. 각 영역은 구현→단위→독립 검증→통합→두 역할 E2E 순서를 유지한다.
