# ADR-004 공급 가능 수량의 소비 범위

상태: adopted (위임된 에이전트 채택), 2026-09-21. 제안 root, 독립 제품 검토 research·상태 검토 method_auditor 모두 채택 동의. 사용자 직접 결정으로 표시하지 않는다.

policy_keys: supplier.remaining_capacity, supplier.shortfall_no_replenish. scope: 브라우저 한 탭 모의 공급. depends_on: D-44, ADR-002. 검토: docs/execution/run-20260921/adr004-product-review.md 및 adr004-state-review.md.

## 공백과 목적

R-03의 `available_order_qty`가 회차 한도인지 남은 발주 가능 물량인지 모호하면 중복 발주나 부족 확정 직후 반복 발주가 생긴다. 고객의 유효 수요를 보존하면서 경영주가 현재 공급 조건 안에서 보수적으로 승인하는 목적은 유지한다. 관련 CORE-06/07/08/25, ADR-002의 수요·기존 진행량·공급 pool·예산 계약을 대체하지 않는다.

## 제안

- 세션·점포·SKU 조건의 `availableOrderQty`는 현재 모의 공급자가 **추가로 접수 가능한 수량**인 비음수 정수다. 소매점 `stockQty`, 확정 공급 pool과 별개다.
- 승인 시 최신 조건 revision 및 capacity를 같은 SQLite 트랜잭션에서 재검증하고 승인 수량만큼 감소시킨다. 여러 라인 중 하나라도 실행 집합의 조건을 위반하면 승인 전체를 rollback한다.
- 공급이 적게 확정돼도 capacity를 자동 복원하지 않는다. 공급자가 접수했다가 확보하지 못한 물량이라는 모의 의미이며, 고객의 부족 수요는 기존 계약대로 다시 pending에 남는다. 부정확한 최신 공급 조건에 따라 동일 부족 발주를 즉시 반복하지 않는다.
- 경영주 데모 조건 변경에서 `추가 접수 가능 수량`을 새 절대값으로 명시 확인하여 갱신할 수 있다. 해당 SKU 조건 revision을 올리고 최신 수요/예산/발주를 다시 계산한다. 주문 취소 기능을 새로 추가하지 않는다.
- 화면에서 모의 공급량, 점포 재고, 진행 발주, 확보/미확보를 분리한다. 0이면 공급 가능 수량 부족 사유를 표시하고 고객 수요는 취소하지 않는다. 예산 부족으로 승인 실패하면 capacity도 감소하지 않는다.

## 대안과 반례

매 승인마다 같은 최대치를 재사용하는 대안은 최신 수요가 있어도 공급자의 모의 최대 접수량을 무제한 재사용하므로 기각 제안. 부족 확정 시 자동 복원은 자동발주 이벤트가 같은 부족을 반복할 수 있어 기각 제안.

검증: 정상 8개 수요/capacity10→8승인/capacity2; replay→동일결과/capacity2; 두번째 신규수요3→현조건 최대2와 MOQ에 맞게 계산; stale revision→rollback; 공급8중3확정→capacity2유지/부족5pending; 명시capacity10재설정→유효부족 수요만 보수 재발주; 예산부족 및 저장실패→capacity와예산 모두rollback. 자동 정책 off에서는 갱신이 승인 없는 수동 발주를 만들지 않는다.
