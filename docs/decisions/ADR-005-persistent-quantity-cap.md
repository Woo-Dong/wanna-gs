# ADR-005 지속 정책의 상품별 수량 상한

상태 adopted (위임 채택), 제안 root, 2026-09-21. research 제품 검토·method_auditor 상태 검토가 모두 채택 권고했다. 검토 기록은 docs/execution/run-20260921/adr005-product-review.md 및 adr005-state-review.md다. policy key merchant.policy_quantity_cap, depends_on ADR-002/004, CORE-05/06/07/25 및 AC-07/08/31.

## 공백과 목적

모델은 이번 묶음의 상품별 수량 제한을 해석할 수 있으나, ‘앞으로도 이렇게’로 만든 정책에 그 제한을 저장할 필드가 없다. 예산·상품 제외만 저장해 수량 제한을 무시하면 명시한 정책보다 많이 발주하는 문제가 생긴다. 수요 보존·과잉 금지·한 번의 묶음 검토라는 목적을 유지한다.

## 제안

- 정책에 nullable 양의 정수 `maxQuantityPerReview`를 저장한다. null은 추가 상한 없음, 값은 **검토 이벤트 한 번에서 각 SKU에 새로 발주할 수 있는 최대 수량**이다. 일일 누적 수량이나 고객 수량 제한으로 설명하지 않는다. UI 정책 확인에 이 단위를 명확히 표시한다.
- ‘이번만’ 모델 maxQuantity는 현재 proposal maxQuantities로 매핑하고, ‘앞으로도’는 별도 확인 후 해당 정책 필드로 저장한다. 값 0·서로 다른 SKU별 복수 상한·기간이 불명확한 일일/주간 누적 제한은 이 필드로 조용히 바꾸지 않고 명확한 지원 범위를 안내한다. 예산/상품 범위/수량 상한을 한 정책 확인에서 함께 보여준다.
- 자동 검토는 원래 ADR002가 허용한 외부 이벤트 하나에 점포당 최대 한 번만 실행한다. 자기 발주 생성 자체를 새 검토 이벤트로 재귀 실행하지 않는다. 동일 이벤트/명령 재전송은 멱등이다. 화면 새로고침 등 새로운 허용 이벤트의 추가 발주도 미확정 coverage·확정 pool·예산·capacity를 먼저 차감한다.
- 최종 발주량은 유효 미발주 필요량, 공급 가능량, 예산, 정책 수량 상한을 넘지 않고 MOQ/배수로 내림한다. 상한 때문에 MOQ에 미달하면 과잉 보충하지 않고 보류한다. 수요를 삭제하거나 추천을 수요에 합산하지 않는다.
- 지속 정책 변경은 경영주의 명시 확인 후 버전을 올린다. 모델 제안만으로 활성화하지 않는다. 기존 정책을 수량 제약 없는 데이터로 읽을 때 null이 기본값이다. 정책 해제 시 다른 제한을 지우지 않아 재활성화 확인에서 전체 조건을 볼 수 있다.
