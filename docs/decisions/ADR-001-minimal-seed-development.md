# ADR-001: 최소 seed로 기반 개발 시작

- 상태: adopted. 문서·의존성 검토 완료, 앱 실행 검증은 미실행.
- 날짜: 2026-09-21.
- 권한 근거: D-21·D-28의 세부 구현·운영 방식 위임. 사용자 직접 확정 결정으로 기록하지 않는다.
- policy_key: development.seed_dependencies
- effective_scope: 현재 설계와 이후 구현 작업 계획. 실행 게이트 통과를 뜻하지 않는다.
- 관련 요구: CORE-14·17·18·22, AC-21~27. 최종 상품·실제 점포·조사·평가 범위는 유지한다.
- depends_on: D-21·D-25·D-26·D-28·D-30.
- supersedes: 이전 WORKPLAN의 D02→D03 및 D05→F00 선행조건. 대체하는 과거 ADR은 없다.
- conflicts_with: 없음. 중간 Production 허용이나 최종 G5/G6 변경은 포함하지 않는다.

## 문제와 선택

기존 계획은 전체 상품·좌표 수집이 끝나야 스키마와 기반 기능을 만들 수 있었다. F00의 SEED-READY 대기만 없애도 스키마의 D02 대기는 남는다. 자료 계약과 전체 수집, 최소 seed와 전체 seed를 나누어 이 의존성을 해소한다.

```text
P03 → D01 평가 계약, D02A 자료 계약
D02A → D02B 전체 자료 수집
D01 + D02A → D03 스키마 → D04A 최소 seed/importer
P04 + D04A + XR-F → F00 → 기능별 구현
D02B + D04A → D04B 전체 import → D05 SEED-READY
D05 → N01, Q01, Q02, G5
```

## 적용 조건

1. D04A는 정상·모호·미식별·공급 부족·예산·결제 실패·중복·48시간 경계를 검사할 최소 데이터를 만든다. 고정 ID·출처/합성 표시·스키마 버전·FK·반복 삽입과 격리를 D-44의 실제 sql.js SQLite에서 독립 검증한 상태를 SEED-MIN-READY로 기록한다.
2. 초기 조사와 데이터 계약은 먼저 수행한다. P03/R04는 자료 접근·표본·좌표 확보 계획과 미확인 범위를 검토하며, 실제 좌표 전수 확보를 요구하지 않는다. D01은 평가 계약이며 전체 평가 데이터 생성 완료를 D03 선행으로 요구하지 않는다.
3. D04A의 importer·정적 factory·테스트 초기화는 DB 도구로 검증한다. 아직 없는 F00의 앱 세션/reset API·UI를 호출하지 않는다. F00이 공통 importer를 소비해 앱 기능을 구현한다.
4. 좌표와 무관한 G1~G3와 합성 위치를 표시한 사전 브라우저 검사는 계속한다. 실제 점포·좌표·거리·지도 연결 검사는 blocked/not_run으로 남긴다. minimal-seed의 U01/U02는 G4-ready 또는 사전 UX 결과이며 정식 Q01/Q02·G4 PASS를 대체하지 않는다.
5. D04A와 D04B는 같은 스키마·importer를 쓴다. 스키마·마이그레이션·importer는 DBA 한 명이 변경한다. 전체 seed 추가가 계약을 바꾸면 소비자에게 통지하고 영향받는 결과를 stale로 처리한다.
6. D05의 자료 조회는 기반 reader로 수행하며 FS/U01/N01/Q01 완료를 요구하지 않는다. 전체 seed를 적용한 뒤 검색·점포·권한·reset·브라우저의 영향받는 검사를 다시 실행한다. N01/Q01/Q02와 최종 G5는 전체 seed 증거를 요구한다.
7. D-44의 200개 이상 상품·검증된 실제 점포·독립 평가셋과 live G5/G6는 최종 완료 조건으로 유지한다. 최소 seed 성공을 CORE-14·22 완료로 표시하지 않는다.

## 독립 검토

- review_seed_proposals: 자료 계약/수집 분리 없이는 병목이 남음을 확인. P03/R04·D01·D04A·D05의 역의존과 전체 seed 전환 후 재검증 조건을 제시했다.
- review_release_proposals: 위임 범위 내 수정 채택에 동의. D04A가 F00 앱 API를 기다리지 않을 것, D05 전 G4-ready와 정식 G4 판정을 구분할 것을 요구했다.
- 두 검토자의 조건을 본문과 WORKPLAN·10·14·19·GOAL에 반영한다. 의미상 검토와 DAG 검사는 앱 단위/통합 테스트와 구분한다.

## 재검증과 복구

구현자는 작업 시작 시 이 ADR과 갱신된 계약 버전을 ACK한다. 기존 실행 증거는 없으며 향후 최소→전체 seed 변경의 영향을 추적한다. 초기 importer가 전체 자료를 수용하지 못하면 DBA가 계약과 migration을 수정하고 관련 검사를 다시 수행한다. 실패를 해결하려고 전체 데이터 요구를 줄이지 않는다.

## D-44 후속 적용

사용자 직접 결정으로 실행 DB를 PostgreSQL에서 브라우저 SQLite로 변경했다. 이 ADR의 최소 seed 의존성 분리는 유지하고 원래 두 검토자가 SQLite 구현까지 검증했다고 주장하지 않는다. 현재 앱/SQL/WASM 증거는 미실행이며 29번과 갱신된 G2~G6에서 검증한다.
