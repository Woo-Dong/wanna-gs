상태: 2026-09-22 사용자 직접 결정. 에이전트가 추정한 품질 면제가 아니다.

사용자 지시: “더이상 높은 품질을 지향하려는 목표는 이제 포기하고, 기능적으로 이슈가 크지 않는 이상 배포와 최종 main branch 병합 등 마무리 하자”

## 변경한 완료 범위

추가 자연어 후보·새 holdout·사용성 비교 최적화를 종료하고 현재 C11의 기능 릴리스를 마무리한다. 기존 정량 자연어 최소 기준과 반복 UX 비교를 최종 병합의 선행조건으로 계속 요구하지 않는다. 원래 G5 전체 품질 목표의 미충족을 PASS로 바꾸지 않으며 별도 `D50-functional-release` 게이트로 구분한다. 기존 GOAL·CORE·ADR의 더 높은 품질 완료 조건과 충돌하는 부분에는 이 최신 직접 지시가 우선한다.

기존 C11 보호 v3 결과75/84 FAIL, 이전 실패·비용·미실행 UX 이력은 보존한다. 파생 공개 validation84/84 두 회와 보호 평가 실패를 혼동하지 않는다. 알려진 한계는 잘못된 상품 후보, 불필요한 확인 질문, 미식별/모호한 입력 행동, 이전 대화 해석, 경영주 되돌리기 제안의 오류다. 자연어 결과를 모든 상황에서 정확하다고 주장하지 않는다.

## 유지하는 기능 출시 조건

- 현재 앱의 결정적 테스트·타입·빌드와 독립 검토를 통과한다.
- 독립 고객·경영주가 정확한 Preview에서 실제 모델·브라우저·SQLite 정상 흐름과 고정 예외를 확인한다. 고객 동의, 상품/점포/수량/가격, 명시 승인, 공급·모의 결제·입고·정확한48시간·중복 처리·복원 등 주요 기능에 미해결 중대 문제가 없어야 한다.
- 두 관점의 최종 기능/정책 검토에서 중대 기능 문제0을 확인한다. 의미 해석의 알려진 한계와 사용자가 확인·승인하는 경계를 함께 보고한다. 단위 검사나 mandatory0만으로 실제 거래 안전성을 대신하지 않는다.
- 단계별 commit/push·PR·CI를 유지하고 최종 integration→main 병합 및 정확한 main source의 Production 배포를 확인한다.
- 제출 URL에서 익명 접근, 두 역할 실제 모델/SQLite 흐름, 상태 복원·기한·reset과 실제 배포 자산의 비밀값 비노출을 최종 검증한다. 이는 D50 범위의 최종 기능 검증이며 원래 품질 G5 통과를 뜻하지 않는다.

API $20/2400, 기존 장부와 실패 기록, 구매·자동충전 금지, 사용자 동의와 모의 거래 경계는 그대로다. 실제 주요 기능 실패가 발견되면 필요한 최소 복구와 영향 검증을 수행하고 숨기지 않는다. 작업 공간·세션·원본 증거를 보존한다.
