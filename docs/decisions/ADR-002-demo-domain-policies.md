## 목적 보존

자연어 상품 확인·명시 동의부터 보수적 발주·확보·모의결제·입고 후 48시간 수령까지 정상 흐름을 유지한다. 모든 요청 거절·확보 전 결제·미입고 수령·동의 없는 대체·초과 발주를 금지한다. D-40 미채택 팀원 기능을 가져오지 않는다. 아래 값은 GS 실제 정책이 아닌 재현 가능한 데모 정책이다.

## 제안과 대안

부분 배정·재고 판매·무기한 동의는 상태/동의 의미를 늘리므로 첫 데모는 전량 FIFO·기한 있는 동의·잔량 보존을 선택한다. 명시적 재동의는 정상 복귀를 가능하게 하며 예약·픽업 시간과 결합하지 않는다.

## 상태·집계 계약

유효 미확보 수요는 pending·동의유효·현재조건일치이며 아직 allocation/reservation이 없는 수량이다. 신규 발주 가능 수요는 여기에 진행중 order link와 같은 조건의 미배정 확보 잔량을 제외한 양이다. review_required/cancelled/payment_failed/reserved/collected/expired와 미식별/추천은 신규 발주 수요0. 확보 잔량이 선두 전량에 부족해도 이미 확보된 수량을 다시 주문하지 않는다. 모든 조회는 한 SQLite snapshot에서 요청별 집계 후 join하며 고객 상세 합계와 다르면 승인 차단한다.

## 1차 독립 반례의 보완 계약

- **source 보존:** line별 확정 확보량 = 미배정 pool + 유효 실패점유 allocation + 결제성공 귀속량. 결제성공 귀속량 안의 입고대기/픽업가능/수령/기한초과는 상호배타이며 reservation/event를 별도 재고로 더하지 않는다. 만료 예약은 pool로 돌리지 않는다. 물리 공급의 source line 연결은 취소/재동의 뒤에도 이력으로 보존한다.
- **진행중 link:** 미확정 발주만 active link이며 해당 line 공급최종 확정 시 그 line link를 모두 비활성화하고 확보량을 source pool로 전환한 뒤 FIFO 배정한다. 고객 취소/미결제 동의부적합 시 해당 요청의 link만 해제하며 제출 발주는 유지한다. 미연결 진행 공급은 별도 표시하고 신규 발주 검토에서 같은 세션/점포/SKU/호환가격의 미확정 물량도 이미 발주한 coverage로 한 번 차감한다. 미확정 물량을 확보/결제로 표시하지 않는다. 취소 뒤 다른 유효 수요가 생겨도 이미 발주한 물량을 다시 발주하지 않는다.
- **발주 산식:** 같은 호환조건 그룹의 신규 발주 필요량 = max(0, 유효 pending 수량 − 미배정 확정 pool − 진행중 미확정 주문량). allocation/결제실패점유/성공예약은 pending에 중복 포함하지 않는다. 요청3/확보2면 필요1, 그1 발주중이면 필요0, MOQ가6이면 초과 보충하지 않고 보류한다. 신규 발주 승인은 실제 pending에만 link하며 이미 확보 pool과 진행중 coverage를 이중 차감하지 않는다.
- **늦은 배정/입고:** allocation은 source line별 사용 수량을 저장한다. 여러 source가 연결된 예약은 전량 입고 전 confirmed/마감없음. 마지막 source 입고 또는 이미 입고된 잔량의 최초 결제 성공 때 같은 transaction에서 pickup_ready·알림·최초 deadline을 만든다. 실패결제 재시도 성공도 이 조건을 재평가한다. 어느 트리거든 기존 deadline은 변경하지 않는다.
- **결제cycle:** 각 retry 전 동의·현재가격·상태·generation·cycle 및 공통 clock을 재검사한다. 동의만료/조건변경/취소/now>=점유마감/두번째 실패 중 먼저 확정된 사건은 점유를1회 해제한다. 알려진 실패만 재시도 가능하며 결과미확인은 기존 command 조회. 재동의는 이전 cycle을 닫고 새 consent version·새순번·새cycle(최초+명시retry 총2회)을 만든다. 이전 cycle command는 새 물량 소비 금지.
- **예산장부:** 승인시 KST budget_day·매입단가·총 점유액 snapshot 고정. 공급최종 확정의 해제/확보는 원 승인일·원 매입가 장부에만 반영한다. 다음날 used나 현재 매입가로 환산하지 않는다. 정책 예산 변경은 현재일/미래 신규 승인에 적용하고 과거 장부 불변, 현재일 사용액 미만 거절. time jump로 기존 장부 귀속 이동 금지.
- **대체 전환:** 추천 열람/거절은 원요청 불변. 고객이 '원요청 대신 전환'을 명시하고 새 SKU·수량·점포·가격·동의를 확인하면 허용된 결제전 원요청 취소와 새 요청 생성을 하나의 로컬 transaction으로 처리한다. 원요청 취소불가/새요청 실패 시 둘 다 불변. 추가 구매는 별도 명시 선택이며 전환으로 표시하지 않는다. 새 요청은 새순번, 기존 결제성공 건은 대체 전환 불가. 명시적 취소+새요청 UX를 지원하더라도 원요청 유지 여부를 숨기지 않는다.
- **멱등성:** 같은 command ID/같은 payload fingerprint는 저장된 결과, 다른 payload는 IDEMPOTENCY_CONFLICT. 역할·세션·generation 경계는 결과 재사용 전에 검증한다.

반례 회귀는 두 독립 보고서의 숫자와 경계를 그대로 task/test에 연결한다. 이 보완은 서로 다른 두 독립 검토자의 2차 채택 동의를 받았다. 테스트 PASS가 아니다.
