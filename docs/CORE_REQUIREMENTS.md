# 핵심 요구사항·서비스 원칙

최초 구현 기준 · 사용자 정의의 짧은 실행 요약. 상세 근거는 [결정 원장](02-decisions-and-open-questions.md)이다. 최신 사용자 지시가 우선하며 에이전트 정책은 이 내용을 조용히 변경할 수 없다. 표의 ID는 작업·ADR·테스트·최종 보고서가 공통으로 참조한다.

서비스 가치: 고객이 원하는 상품의 수요를 드러내고, 경영주 업무를 늘리지 않는 보수적 발주와 예측 가능한 픽업으로 연결한다. 품질을 우선하되 해커톤의 모의 운영 범위를 유지한다.

| ID | 핵심 요구 | 주요 증거 |
|---|---|---|
| CORE-01 | 실제 GS 연동·실제 청구 없는 프로토타입, 출처 사실과 모의 거래 구분 | 화면 안내·provider/seed 모드 |
| CORE-02 | 고객 입력은 자연어, 사진/링크 입력·레시피 제외 | 입력 UI/API 및 거절 사례 |

| CORE-04 | 한 요청은 한 상품/점포, 수량·가격·자동 구매 동의 기록 | 요청/동의 DB·브라우저 |
| CORE-05 | 경영주 묶음 요약·자연어 지시·수동 승인과 사전 승인 정책 | 경영주 UX·명령 eval |

## 권한 경계

위임 정책은 사용자 정의 안에서 선택한다. 고객/경영주의 런타임 확인·동의·승인은 별개다. 실제 생산 재고·판매가·점포 영업 상태를 합성값으로 주장하지 않는다. 실제 운영 수준의 UX 목표는 실결제·실GS 통합 운영 인증을 뜻하지 않는다. 긴 작업 허용은 새 유료 구매나 계정 사용량 한도 무시를 뜻하지 않는다.

## 사용 방법

모든 작업 계약에는 관련 CORE ID, 적용 ADR/계약 버전, 테스트 기대값을 넣는다. 최종 목표는 이 표의 필수 항목을 코드·증거에 연결한다. 결정의 현재 유효 상태와 대체 이력은 [DECISION_INDEX.md](DECISION_INDEX.md)에서 확인한다.

[card.md](../card.md)는 이 요구를 작업·복구·재개에 연결하는 안내다. D-32~34의 유동적 작업 경로·단일 문서 기준·목적 보존 지침은 02번에 있으며 제품 범위를 추가하거나 기존 CORE를 대체하지 않는다.
