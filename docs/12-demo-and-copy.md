# 데모 구성·표현·향후 가치

## 핵심 데모 이야기

고객은 정확한 상품명을 몰라도 원하는 상품을 확인해 요청한다. 경영주는 이미 팔린 수량에 더해 아직 충족하지 못한 요청을 보고, 묶음 지시와 보수적인 자동발주로 대응한다. 확보된 물량은 요청 순서대로 예약되고 고객에게 수령 시각을 명확히 알려준다.

## 권장 시연 순서

1. 데모 세션을 초기화하고 고객/경영주 화면을 같은 세션으로 연다.
2. ‘그 딸기 들어간 빵 같은 거’로 검색하고 구분 질문·상품 확인을 보여준다.
3. 수량·점포·가격·자동 구매·48시간 조건에 동의해 요청한다.
4. 경영주 화면에서 기존 요청과 합산된 수요를 확인한다.
5. ‘샌드위치는 빼고 나머지는 요청만큼, 예산 안에서’ 등 수정 동작을 다른 준비된 묶음에서 보여준다.
6. 자동발주 조건 충족 품목은 처리되고 최소 수량 미달 품목은 보류되는 것을 확인한다.
7. 공급 확정 → FIFO 배정 → 모의 결제 완료 → 예약 확정을 보여준다.
8. 입고 → 픽업 가능 알림 → 48시간 마감 표시 → 모의 수령을 보여준다.
9. 별도 초기화 사례에서 미식별과 48시간 초과를 짧게 확인한다.

하나의 시연에서 서로 모순되는 명령으로 핵심 상품을 제외하지 않도록 fixture를 준비한다. 정상 흐름과 예외 흐름의 데이터를 분리한다.

## 카피 가이드

장난스러운 제목 아래에는 정확한 행동·상태·기한을 설명한다. 재미있는 카피가 구매 확정 여부를 흐리지 않게 한다.

| 상황 | 제목 | 정확한 설명 예시 |
|---|---|---|
| 입력 | 없으면 말하GS | 찾는 상품의 이름이나 특징을 알려주세요. |
| 후보 확인 | 이 상품 맞으시GS? | 이름·맛·용량을 확인해주세요. |
| 요청 접수 | 원하GS, 접수했GS | 선택한 점포에 요청을 남겼어요. 아직 물량 확보 전이에요. |
| 집계 | 지금 3명이 원하GS | 사람 수와 요청 수량을 구분해 표시한다. |
| 자동 구매 동의 | 확보되면, 담아두GS | 물량이 배정되면 동의한 조건으로 모의 자동 결제돼요. |
| 예약 확정 | 결제됐GS, 기다려주GS | 모의 결제와 예약이 완료됐어요. 입고 후 알려드릴게요. |
| 픽업 가능 | 여기 있GS | 9월 22일 오후 3시까지 수령해주세요. 날짜는 실제 데모 상태로 계산한다. |
| 제한 | 지금은 못 구하GS | 확인된 제한 사유를 덧붙인다. 공급 종료와 일시 제한을 구분한다. |
| 미식별 | 못 찾았지만, 남겨두GS | 상품 확인이 되지 않아 구매 요청·예약으로 접수된 상태는 아니에요. |
| 자동발주 결과 | 알아서 처리했GS | 적용 정책·상품·수량·금액 요약 |
| 예외 검토 | 이것만 봐주GS | 자동 처리하지 않은 이유와 선택 가능한 행동 |
| 대기 | 조금 더 기다리GS | 재검토 조건과 현재 확인된 상태 |

`이런 거 찾았GS`는 웹 신상품 발굴을 구현할 때의 후속 카피이며 이번 화면 기능으로 넣지 않는다.

## 항상 구분할 표시

- 데모 데이터: 실제 GS 상품 취급·재고·공급 현황이 아님.
- 데모 결제: 실제 청구 없음.
- 실제 AI / 시나리오 모드: LLM 장애를 숨기지 않음.
- 예약 확정 / 픽업 가능: 별도 사건.
- 고객 수 / 요청 수량 / 발주 수량 / 확보 수량: 서로 다른 지표.

## 본부에 대한 향후 가치: 화면 구현 없음

미식별·미충족 요청이 운영 중 축적되면 상품명/검색 경험 개선, 신규 취급 검토, 지역별 수요 관찰에 활용할 수 있다. 이는 미래 가설이다. 이번 프로토타입이 본부 수요 지도·자동 상품 기획·정확한 판매 예측을 제공한다고 발표하지 않는다.

후속 확장: 사진·링크·레시피, 인근 점포 합산, 임박 재고 역매칭, 판매·수령 결과 기반 추천 개선. 사용자 검증과 실제 업무 연동이 선행돼야 한다.

## 제출 설명에 포함할 것

문제 가설, 구현한 사용자 흐름, 에이전트가 필요한 두 지점, 코드로 강제한 거래 규칙, 실제 모델/DB 실행 증거, 가상 데이터와 모의 결제의 범위, 비용·접근 제한, 본부 활용을 포함한 향후 가치.

## 시연에서 밝혀야 할 전제

모든 공급·결제·입고 데이터는 모의이며 모델 live/fixture 모드를 명확히 표시한다. 상태 설명은 모델의 제안과 실제 완료를 구분한다. 48시간 수령 기한과 구매 의사 유효기간은 별개다. 참고한 실제 점포와 구분해서 설정한 모의 영업시간·신선도 처리, 시연 viewport, 심사 접근 방식은 13번 R-15/R-30/R-37/R-39에서 최종 결정한다.
