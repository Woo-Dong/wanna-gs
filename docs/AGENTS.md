# docs 문서 작업 규칙

## 읽기

`README.md`, `02-decisions-and-open-questions.md`, `PROGRESS.md`를 먼저 읽는다. 구현을 준비할 때 `GOAL.md`와 해당 영역의 명세·테스트를 함께 읽는다.

## 정확성

- 문서는 한국어로 작성한다. 코드·필드 이름은 영어를 사용해도 된다.
- 사용자 직접 확정, 사용자 위임에 따른 에이전트 채택, 기술 기준선, 제안, 미정, 폐기 결정을 구분한다.
- 본부 기능, 사진·링크·레시피, 실제 GS 연동·실제 결제는 현재 범위로 되살리지 않는다.
- 현재 GS 서비스의 기능·정책은 검증되지 않은 문제 가설로 취급한다.
- 무료 티어·모델 접근·인증 정보는 출처 날짜와 실제 검증 여부를 기록한다.
- 계정 비밀정보나 토큰을 문서·로그·커밋에 기록하지 않는다.

## 변경과 인계

- 정책 변경은 결정 기록, 관련 명세, 검증 기준을 같은 작업에서 갱신한다.
- `PROGRESS.md`에 수행한 일, 증거 위치, 막힌 부분, 다음 행동을 남긴다.
- 테스트 미실행·모의 응답·실제 LLM 응답을 구분한다.
- 외부 사례는 설계 참고이며 현재 프로젝트의 성능 증거로 사용하지 않는다.
- 이 문서는 `docs/` 범위의 지침이다. 프로젝트 전체 규칙은 `../AGENTS.md`를 따른다. 검토용 제안·독립 문서 감사·앱 실행 검증을 구분한다.

## 검토·검증 문서 동기화

정책 공백은 13번 검토 목록과 02번 결정 원장을 연결한다. 서브 에이전트/게이트 변경은 14번, 복구 변경은 15번과 프로젝트 스킬을 맞춘다. Markdown 구조 검사나 스킬 양식 검증을 앱 단위/통합 테스트 통과로 보고하지 않는다.

## 자율 결정과 이력

세부 O/R 정책은 17번 ADR·두 독립 검토·채택·검증 절차로 해결한다. 과거 사용자 의논 문구를 사람 대기 조건으로 되살리지 않는다. Git/릴리스는 16번, 사전 환경 점검은 18번 및 GOAL에 맞춘다. 검토 기록은 당시 결과와 한계를 보존한다. 중복·임시 리뷰는 결론과 필요한 증거를 유지하는 통합 기록으로 정리한 뒤 삭제할 수 있다.

## 추적

핵심 요구는 CORE_REQUIREMENTS, 현재 유효한 위임 결정은 DECISION_INDEX를 읽는다. 사용자 추가 정의는 02에 기록하고 위임 정책은 proposed ADR→독립 검토→채택→index/명세/테스트 동기화 순서를 따른다. 조사·데이터·자연어 개선과 운영 변경은 19~24번에 맞추고, 새 조사 결과가 사용자 확정 기능을 조용히 바꾸게 하지 않는다.
