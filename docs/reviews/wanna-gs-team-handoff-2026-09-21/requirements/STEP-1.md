# [STEP-1] 고객 요청 목록·모집 현황

상태: 기존 구현에서 요구사항 추출
작성일: 2026-09-21
선행: 없음

## 목적

경영주가 고객이 원하는 상품과 모집 현황을 한눈에 확인한다. 조회만으로 수요를 파악하고 고객별 추가 응대를 요구하지 않는다.

## 요구사항

- 점포별 고객 요청 상품을 카드 목록으로 표시한다.
- 카드에 상품 이미지·이름, 신청 인원, 신청 수량, 모집 목표, 진행률, 추가 필요 수량, 모집 기한을 표시한다.
- 모집 목표는 최소 발주 수량 한 묶음이다. 사람 수와 상품 수량을 구분한다.
- 추가 필요 수량은 목표에서 유효 신청 수량을 뺀 값이며 0 미만으로 표시하지 않는다.
- 목표 달성 시 모집 완료를 표시한다. 이 단계에서는 발주하지 않는다.
- 요청이 없으면 빈 목록을 안내하고, 조회 실패는 빈 목록과 구분해 재시도할 수 있게 한다.
- 새로고침·앱 재실행에도 DB에 저장한 요청을 유지한다.
- 가상 점포·고정 기준 시각을 사용하는 데모임을 안내한다.

## 완료 기준

- 3명이 4개를 신청하고 목표가 6개라면 `3명 · 4/6개 · 2개 더 필요`로 표시한다.
- 6/6개면 모집 완료·진행률 100%가 표시되며 발주가 발생하지 않는다.
- 요청 없음·조회 실패 상태를 서로 구분한다.
- 신청 취소는 유효 수량 합계에서 제외하고 모집 목표 초과 신청은 거절한다.

## 데이터·제외 범위

- 점포, 상품, 고객, 모집 회차, 고객 요청을 저장한다. [확정 DB 스키마](../database/SCHEMA.md).
- 목표 수량은 회차 시작 시 정해져 상품의 발주 단위가 바뀌어도 기존 회차에서 유지된다.
- 발주 승인, 자동 설정, 고객 앱 입력 화면, 인증·결제·실제 수령 처리는 이 단계에서 제외한다.
- 기존 구현을 정리한 문서이며 이번 추출 과정에서 구현을 새로 검증하지 않았다.
