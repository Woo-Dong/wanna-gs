# [STEP-6] 입고 확인·고객 수령 가능 표시

상태: 요구사항 초안 / 구현 미승인
작성일: 2026-09-21
선행: 발주 결과 기록, STEP-5의 회차 구분

## 목적

발주한 상품의 실제 입고를 확인하고, 고객에게 수령 가능한 상태를 보여준다.

## 요구사항

- 발주 접수와 입고 완료를 구분한다. 발주 성공만으로 수령 가능을 표시하지 않는다.
- 발주 건에 연결된 입고 수량·시각을 기록한다.
- 입고된 상품을 해당 회차의 고객 요청과 연결하고, 확보된 수량에 한해 수령 가능 상태를 표시한다.
- 경영주 화면에는 발주 수량, 입고 수량, 수령 가능 안내 대상 수량을 구분해서 보여준다.
- 고객에게 대상 상품·점포·수령 가능 여부를 표시한다. 경영주의 개별 메시지 작성은 요구하지 않는다.
- 입고 이벤트는 실제 운영에서 기존 시스템 연동을 전제로 한다. 데모에서는 모의 입고 이벤트를 사용한다.
- 동일 입고 이벤트를 다시 받아도 수량과 고객 안내 상태가 중복 반영되지 않는다.
- 부분 입고는 전체 입고와 구분한다. 물량이 확보되지 않은 고객에게 수령 가능을 표시하지 않는다.

## 완료 기준

- 발주 성공·미입고 상태에서는 수령 가능이 표시되지 않는다.
- 입고 확인 후 확보된 고객 요청에만 수령 가능이 표시된다.
- 안내 대상 총수량은 확인된 입고 수량을 초과하지 않는다.
- 같은 이벤트를 반복 수신해도 결과가 동일하다.

## 구현 전 결정·데이터

- 부분 입고 시 배정 순서·요청 일부 배정 허용 여부는 미정이다. 구현 전에 합의한다.
- 입고 이벤트 식별자, 발주 연결, 입고 수량·시각, 고객별 안내 상태의 스키마를 정의해야 한다.
- seed 후보: 미입고, 전량 입고, 부분 입고, 중복 이벤트. SQL은 구현 단계에 작성한다.
- **수령 가능 표시는 이번 요청에 따라 유지한다.** 실제 수령 확인·픽업 코드·기한·미수령·예약 점유 해제는 제외한다.
- 실제 외부 알림 발송은 별도 승인 대상이다. 검증은 아직 실행하지 않았다.
