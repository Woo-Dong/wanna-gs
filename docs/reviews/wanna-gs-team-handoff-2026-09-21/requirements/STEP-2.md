# [STEP-2] 경영주 수동 발주

상태: 기존 구현에서 요구사항 추출
작성일: 2026-09-21
선행: STEP-1

## 목적

모인 수요를 경영주가 한 번 승인해 발주로 연결한다. 고객별 답변이나 발주 수량 재입력을 요구하지 않는다.

## 요구사항

- 모집 완료 상품에 목표 수량과 발주 승인 버튼을 제공한다.
- 서버가 모집 완료 여부와 실제 유효 신청 합계, 공급 가능 여부, 기한을 다시 검사한다.
- 승인 처리 중 중복 클릭을 막고 접수 결과·실패 사유를 표시한다.
- 같은 회차에 중복·동시 승인해도 발주는 한 건만 생성한다. 이미 결과가 있으면 기존 결과를 반환한다.
- 모집 완료와 발주 접수 성공을 구분한다. 접수 성공은 입고·수령 확정이 아니다.
- 공급 불가 또는 기한 경과로 거절된 결과도 이력으로 보존한다.
- 새로고침·재실행 후에도 발주 결과를 유지한다.

## 완료 기준

- 목표 미달 회차는 승인 버튼이 없고 서버에서도 발주를 거절한다.
- 목표 달성·공급 가능·기한 내 회차는 목표 수량으로 모의 접수된다.
- 공급 불가·기한 경과는 원인을 표시하고 성공으로 처리하지 않는다.
- 동시 승인에도 발주 결과는 한 건이며 접수번호가 바뀌지 않는다.

## 데이터·제외 범위

- 모집 회차에 모의 공급 가능 여부를 추가하고 회차별 발주 결과를 저장한다. [확정 DB 스키마](../database/SCHEMA.md).
- 데모에서는 모집 기한을 발주 기한으로 함께 사용한다. 실제 공급사 기한은 별도 정의가 필요하다.
- 자동 발주, 실패 건 재발주, 실제 공급사 연동, 인증·결제·고객 수령 처리는 제외한다.
- 기존 구현을 정리한 문서이며 이번 추출 과정에서 구현을 새로 검증하지 않았다.
