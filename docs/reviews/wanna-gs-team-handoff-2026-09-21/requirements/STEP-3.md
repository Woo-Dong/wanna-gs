# [STEP-3] 상품별 자동 발주 설정·신청 고객 조회

상태: 기존 구현에서 요구사항 추출
작성일: 2026-09-21
선행: STEP-2

## 목적

수요 확인과 설정 화면을 분리하고, 자동 발주 설정을 유지해 반복 조작을 줄인다.

## 요구사항

- 고객 요청 현황과 상품별 발주 설정을 분리된 화면으로 제공한다.
- 점포·상품별 자동/수동 토글을 제공하며 기본값은 수동이다. 다음 모집 회차에도 설정을 유지한다.
- 자동 설정 상품은 유효 요청 수량이 목표에 도달하면 공급·기한을 검사해 모의 발주한다. 화면이 열려 있어야만 실행되는 구조를 피한다.
- 자동 발주 조건에 결제 완료를 추가하지 않는다. 목표 달성은 구매 보장을 뜻하지 않는다.
- 이미 모집 완료된 미발주 회차가 있는 상품을 자동으로 바꾸면 즉시 발주 확인을 받는다. 취소 시 설정과 발주 모두 변경하지 않는다.
- 자동 설정을 꺼도 기존 접수 건은 취소하지 않는다. 실패한 발주를 자동 재시도하지 않는다.
- 설정이 실제로 달라질 때만 변경 전후 값을 기록한다. 발주 당시 자동/수동 방식도 보관한다.
- 신청 인원에서 고객 닉네임·수량·최초 신청 시각을 조회한다. 취소 고객과 연락처는 목록에서 제외한다.
- 저장 결과는 화면을 밀지 않는 공통 고정 토스트로 안내한다. 성공은 4초 후 닫고 오류는 직접 닫는다.

## 완료 기준

- 자동 설정에서 목표 달성 시 모의 발주 한 건, 수동에서는 자동 발주 없음.
- 완료 회차의 자동 전환 확인/취소가 정확히 동작한다.
- 동시 신청·토글·수동 승인에도 중복 발주가 없다.
- 저장 오류 시 해당 트랜잭션의 신청·발주 또는 설정·이력이 함께 롤백된다.
- 같은 설정을 다시 저장해도 변경 이력이 늘지 않으며 고객 목록의 인원·수량이 집계와 일치한다.

## 데이터·제외 범위

- 점포·상품별 설정, 설정 변경 이력, 발주 당시 실행 방식을 추가한다. [확정 DB 스키마](../database/SCHEMA.md).
- 설정 이력 조회 화면은 STEP-4 범위다. 실제 공급사·운영 인증·고객 수령 처리는 제외한다.
- 기존 구현을 정리한 문서이며 이번 추출 과정에서 구현을 새로 검증하지 않았다.
