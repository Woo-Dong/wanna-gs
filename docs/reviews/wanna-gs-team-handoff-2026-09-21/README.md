# 원하GS — 팀 공유용 요구사항·DB 스키마

추출일: 2026-09-21. 이 ZIP은 설계 전달 자료이며 실행 가능한 전체 애플리케이션이나 DB 백업이 아니다.

## 디렉터리

```text
requirements/              STEP-1·2·3·4·5·6·7·9 요구사항 MD
database/SCHEMA.md          확정된 전체 테이블·컬럼·제약·관계
```

## 읽는 순서

1. [전체 DB 스키마](database/SCHEMA.md): STEP-1~4에 정의된 업무 테이블 8개와 관리 테이블 1개.
2. [STEP-1](requirements/STEP-1.md): 고객 요청 목록·모집 현황.
3. [STEP-2](requirements/STEP-2.md): 경영주 수동 발주.
4. [STEP-3](requirements/STEP-3.md): 상품별 자동 발주 설정·신청 고객 조회.
5. [STEP-4](requirements/STEP-4.md): 발주·설정 이력 조회.
6. [STEP-5](requirements/STEP-5.md): 모집 마감·다음 회차·대기 신청 초안.
7. [STEP-6](requirements/STEP-6.md): 입고 확인·고객 수령 가능 표시 초안.
8. [STEP-7](requirements/STEP-7.md): 고객 픽업 단계 제외 기록.
9. [STEP-9](requirements/STEP-9.md): 요청부터 입고·수령 가능 안내까지 실적 조회 초안.

## 합의 상태

- 확정 스키마는 STEP-3까지의 구조이며 STEP-4에서 구조 변경은 없다.
- STEP-5·6·9의 신규 데이터 설계는 아직 미확정이다. 초안 내용을 이미 존재하는 테이블·컬럼으로 해석하지 않는다.
- 고객 픽업 기능은 제외한다. STEP-6의 수령 가능 표시는 유지하며 실제 수령 완료를 뜻하지 않는다.
- STEP-8은 이번 요구사항 추출 요청에 포함되지 않아 동봉하지 않았다.
- 이번 자료 전달은 추가 구현 승인이나 실제 공급사 발주·외부 알림 발송 승인이 아니다.
- 기존 구현 및 검증 결과를 새로 실행한 것으로 주장하지 않는다. 이번 검증은 전달 파일·링크·압축 무결성 확인이다.

## DB 스키마 문서

- database 디렉터리에는 사람이 읽는 `SCHEMA.md`만 포함한다. 테이블명·컬럼명·타입·필수 여부·기본값·PK/FK/UNIQUE/CHECK·관계·단계별 변경을 정리했다.
- SQL, migration 실행기, seed·샘플 데이터는 넣지 않는다. 원 프로젝트 파일은 유지한다.
- STEP-1~4는 기존 구현의 요구사항을 추출했으며, 기존 실행 로그·코드를 전달하는 문서가 아니다.

환경파일, 접속 문자열, 비밀키, 실제 DB 행, Git 이력, node_modules, 빌드 결과물은 포함하지 않았다. 파일은 UTF-8이며 ZIP은 알집 등 일반 압축 프로그램으로 열 수 있다.
