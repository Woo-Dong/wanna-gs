# B0 UX 실패 이후 비교 계약의 읽기 전용 분석

- 작성자 research. 정책 제안/채택·코드 변경·추가 실행 없음. 실제 모델0, 보호 holdout/생성기 열람0.
- 판정: **사용자 목적과 best 정상 기능 검증은 계속 성립한다. 현재 고정한 B0 UX 상대 비교 프로토콜은 미충족이며, 허용된 두 실행의 현존 증거만으로 전체 비교/G5 PASS를 만들 경로는 없다.** 이는 best가 정상일 수 없다는 증명이 아니라 비교 기준선의 증거 결손이다.

## 실제 증거의 도달 범위

최초 result SHA `4989b1053468134ff8a3099b951493ba483687f57fb14de49db48ea4e87b4209`, 지정 recovery result SHA `2b9839efff2d118b48751642e7382b41d6e41fa49b837ccb4beff56fd1433c4b`를 직접 읽었다.

recovery는 clear-1/2/3 각각3PASS, ambiguous는2PASS/1FAIL, 재동의·10SKU묶음·자동정책·예외묶음은 각3미실행이다. 두 run의 모델 호출은3+14=17회이며 workload 실행수15와 다르다. 추가 run을 실행하지 않았고 원본을 변경하지 않았다.

- 명확 요청3종의 실제 성공 조작·시간은 유효한 **부분 관측**이다. ADR006의 전체24 전제 때문에 이를 전체 상대비교 PASS로 재분류할 수 없다.
- ambiguous의 성공2개만 뽑으면 채택한 세 반복 완료 표본이 아니다. 최초 clear-1 성공과 섞어 다른 workload를 채울 수도 없다.
- 나머지4종은 B0 완료시간·조작 관측 자체가 없다. B0 모델이 없던 요청에 어떤 시간으로 성공했을지 추론해 중앙값을 계산할 수 없다.
- 실패 종료시간/도구 대기를 성공 완료시간으로 넣거나 미완료를 무한시간으로 정의하면 best의10% 비교가 자동으로 유리해진다. 이는 현재 완료시간 정의에 없다.

## 계약 모순인가

**논리적 제품 모순은 아니다.** ‘B0 실패’와 ‘새 best 정상’은 동시에 참일 수 있다. docs21/23의 개선 목적도 그 경우를 전제로 한다. 실제 NL336은 품질실패를 보존한 채 후보와 비교할 수 있고, release checker도 NL baseline 품질실패를 허용한다.

그러나 **측정 절차상 도달 불가능한 가지가 생겼다.** 이번 UX 계약은 고정 B0의 완전한 성공 표본을 요구하면서 B0 오류가 나면 전체를 중단하고, 지정된 단 한 번 재측정 이후 추가 실행·새 기준선 선택을 허용하지 않는다. 이제 허용된 실행이 모두 실패했으므로 best가 나중에 완벽하게 동작하더라도 이 과거 B0 표본이24/24로 바뀌지 않는다. 따라서 ‘best가 개선되면 이 비교게이트도 자연히 해결된다’는 전제는 성립하지 않는다.

이것을 모든 미래 조건에서 영구 불가능하다고 확대할 필요는 없지만, **현재 유효 계약·허용 실행·현존 증거만으로는 해당 상대 비교 조건을 충족할 수 없다**고 명확히 기록해야 한다. B0 품질 문제를 수정하면 이미 고정된 B0와 다른 버전이 되므로 이 조건 안에서 기준선을 고치는 경로도 없다. 이 문서는 다른 정책을 만들거나 그 문제를 우회할 권한을 부여하지 않는다.

## 현재 계약에서 계속 가능한 검증

1. **NL 후보 개선:** B0 227/336 및 오류109를 고정한 상태에서 C1 dev 선별·고정 validation paired 평가, 최소기준·범주/mandatory 회귀, 사전 한도 내 후보선택은 진행 가능하다. B0 정확도가 낮다는 이유만으로 후보 정확도를 측정하지 못하는 것은 아니다. 보호 holdout은 최종 best 고정 등 기존 선행조건 이후 평가자만 실행한다.
2. **best 절대 정상/안전:** 해당 후보의 고객 SKU 확인·동의·정상 요청, 경영주 묶음/자동정책, 재동의 복귀, 모델 오류 입력보존, 실제 SQLite/역할별 독립브라우저, 필수100% 및 조작/질문 상한을 기존 배정·예산 안에서 검증할 수 있다. 이 결과는 best 자체의 정상 증거로 유효하되 전체 상대성능 PASS의 대체는 아니다.
3. **best UX 측정:** 기존 예정 best8×3을 수행할 수 있다면 실제 정상성공·동작수·화면이동·시간을 남길 수 있다. B0의 없는 값과10%를 계산하지 않는다. 완료된 B03종과의 기술적 부분 수치는 전체8종 비교 완료와 분리하고, 실패·미실행 표를 함께 둔다.
4. **기존 유효 증거 유지:** fixture24 준비검사, I01 실제 역할 QA, 도메인 불변식 등은 해당 범위·source 일치 조건에서 보존한다. fixture를 B0 live로 바꾸거나 원래 실패를 삭제하지 않는다.

## 현재 확보할 수 없는 결론

- 전체8종의 고정 B0 대비 best 조작/화면 이동 증가0 및 완료시간 중앙값10% 조건에 대한 완성된 비교 판정.
- ADR006이 정한 recovery24/24 정상 및 상대 비교 준비 완료.
- 위 비교가 필수로 연결된 현 G5 manifest PASS와 이를 전제로 한 GOAL 완료. best 절대 정상만으로 상대 비교 미충족을 대신할 수 없다.

완료 불가 범위를 곧바로 ‘best 제품도 실패’라고 넓히거나 모든 작업을 멈출 이유는 없다. 반대로 문서상 선택 최적화 종료를 이용해 이 채택된 편의성 조건을 선택항목으로 바꾸는 것도 허용되지 않는다. 현재는 **best 품질 개선·정상 검증 계속 / 전체 UX 상대 비교 NOT_READY / G5·GOAL 미완료**를 병기하는 것이 사실과 계약에 맞다.

새 B0 선택·추가 재실행·성공표본 선별·fixture 대체·분모 또는 합격선 조정은 제안하지 않았으며 실행하지 않았다. 이 분석은 새 정책 초안이 아니다.
