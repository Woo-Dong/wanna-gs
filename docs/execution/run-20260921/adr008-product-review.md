# ADR-008 제품·출처 독립 검토

검토자 research, 제안자 root. 검토한 ADR 초안 SHA `cd5d7799b06225179ec1c8da633e2a43c8a82e8762796023fce268e03799920b`. **정책 제안 채택에 동의한다.** 검토자 자신은 C11 고객 prompt·UI의 작성자이며 이 보고서는 그 구현의 독립 QA나 C11 품질 승격 승인이 아니다. ADR 제안자는 별도 root이고, 다른 정책 검토자의 결론을 읽기 전에 제품/출처 의견을 작성했다. 실행기 구현·원본/정답 수정·유료 호출·보호 원문 접근은 이 검토에서0이다.

## 출처와 현재 발화의 의미

현재 공개 발화는 빙그레, 맑은하늘 도라지차,500ml 단서를 주며 무라벨 여부를 말하지 않는다. 공식 빙그레 PDT31 페이지의 family41는 무라벨 계열, prod273/val270/500ml이고 family42의 prod271/val268도 같은 상품명·500ml다. 수집 단계에서 후자의 이미 포함된 용량을 다시 덧붙여 이름이500ml500ml가 됐으며 전자의 포장 구분은 모델 catalog에 없다. 이번에 저장된 공식 응답5개의 원본 SHA를 다시 대조했다. C10 전 조사와2026-09-22 직접 원문 조회에서도 같은 사실을 확인했으며 이번 검토에는 추가 네트워크 호출이 없다.

두 demo SKU `DEMO-778B67C87CCC` 및 `DEMO-6AFC6A69B100`는 **주어진 단서에 각각 부합하는 실제 카탈로그 확인 후보**다. 근거는 현재 모델 응답에 그 ID가 나왔다는 사실이 아니라 공식 상품/포장 정보와 공개 입력의 제약이다. 단일 SKU만 정답이라고 하는 것은 사용자에게서 받지 않은 포장 구분을 요구한다. 이름의 반복 토큰·짧은 이름·ID·정렬순서로 첫 SKU를 선호하는 것은 소비자의 식별 조건이 아니다.

이는 두 상품이 동일 GTIN/거래 SKU라는 뜻이 아니다. 가격·수량·점포·동의는 선택한 개별 SKU별로 유지하고, 원요청을 자동 전환하거나 거래를 병합하지 않는다.340ml는 명시 용량과 불일치하므로 이 동등 후보 집합에 포함되지 않는다.

## 정확한 적용 범위와 명세 적합성

공개 dev/validation의 expected와 모든 expected_prior를 두 SKU 기준으로 감사했다. 대상은 **C02-validation-007 expected**와 **C06-validation-006 expected_prior[0]** 두 slot이다. C06 첫턴도 같은500ml 상품명만 주며 포장 차이가 없다. C06 최종 정정 상품과 뒤 턴의 정답은 불변이다. 자세한 읽기 결과는 private `c12-oracle-review/source-and-public-scope.json`에 보존했다.

두 slot 각각 `required_any_skus`와 `candidate_pool` 모두 두 SKU 집합으로 바꾸고 minimum1·allowed_actions·기존 label·턴/범주/분모를 유지하는 제안에 동의한다. **둘 중 하나 또는 둘 모두를 후보로 제시하는 것은 CORE03/ADR003의 고객 확인 후보 찾기 목적에 어긋나지 않는다.** 현재 발화는 상품 계열/브랜드/용량의 확인 후보를 찾기에 충분히 명확하며 사용자가 언급하지 않은 포장 선호를 임의로 추가 조건으로 만들지 않는다. '명확'은 거래 SKU 선택과 구매 동의가 이미 완료됐다는 뜻이 아니다. 확인 후보 뒤 실제 상품·수량·한 점포·가격·명시 동의는 CORE04/ADR002 그대로다. 형식상 confirmationRequired만으로 잘못된 다른 상품 확정을 정당화하는 것도 아니다.

다른 브랜드·용량·상품, 실제 취향/조건 모호함, 미등록·대체 거절의 정답은 넓히지 않는다. 두 slot 밖 oracle diff0을 독립 검사해야 한다. 공개 전체 조사에서 추가로 같은 근거 결함이 확인된다면 몰래 범위를 늘리지 말고 해당 범위를 기록·검토해야 한다.

## 검증 버그 복구와 품질 완화의 경계

단일 SKU의 배타적 정답 근거가 없던 곳에서 유효 집합을 바로잡는 수리이므로, 이 정확한 범위에서는 합격선 완화보다 **정답 결함 복구**로 판단한다. 특히 원문·catalog·app·prompt·scorer·340ml 오류·95/90·회귀0·불완전0을 유지하고 원본 실패를 보존하는 것이 필수다. 실패한 C02만 수정하고 같은 의미의 C06 첫턴을 그대로 두면 현재 후보 편의에 따른 선택 수정이 되므로 동의할 수 없다.

ADR은 모든 이용 가능한 과거 후보/반복의 동일 공개 관측을 새 oracle로 대칭 재채점하고 원점수와 분리하며, generation source/config와 사후 oracle revision을 구별한다. 이 가드는 타당하다. C11 원점수83/84·회귀1FAIL이나 과거340mlFAIL은 사라지지 않는다. 새 정답으로 실제 validation84 두 번을 실행한 뒤 freeze·아직 미실행 v3 보호평가를 최초1회 진행하는 경로는 사후 재채점만으로 승격하는 것보다 별도 실행 근거를 제공한다. 기존 v3의 사전 동결·독립성·미노출은 해당 데이터 검토자 확인 영역이며 이 보고서는 그 원문을 보지 않았다.

현재2400회 한도에서 정적 예약이 실행을 막는 사실을 문서가 명시하고 유료 GO를 하지 않는 점도 확인했다. 실제 상한 변경은 사용자 승인 또는 기존 한도 내 별도 독립 검토된 예약 장치가 선행해야 하며 이 정책 검토가 비용/호출 권한을 늘리지 않는다. QA·UX·G5/G6도 별도다.

## 최신 파생 재채점 경로 정정·ACK

조정자가 검토 도중 갱신한 ADR을 **한 번 읽은 동일 바이트의 내용과 SHA**로 다시 확인했다: `cd5d7799b06225179ec1c8da633e2a43c8a82e8762796023fce268e03799920b`. 앞부분에 기록한 '새 정답으로 실제 validation84 두 번을 실행' 경로 설명은 이전에 읽은 문장에 대한 설명이며 최신 제안에서 삭제됐다. 이 부록이 해당 실행 경로 의견을 대체한다. 최초 읽기와 해시 확인 중 갱신이 교차했으므로 앞부분의 해시만 보고 그 옛 문장이 최신 바이트에도 있다고 해석하지 않는다.

최신 경로는 **이미 별도로 실행된 C11 validation01/02의 전체 관측을 새 oracle로 각각 재채점**한다. 앱/runtime/prompt 및 모델이 실제 본 text/history/state/catalog가 불변임을 검증하면 oracle 정정만으로 같은 모델 호출184회를 다시 요구할 제품적 이유는 없다. 두 실제 run ID·원본 fingerprint·실행 시각·실행 dataset·usage·최초 FAIL은 유지하며, 새 oracle hash·파생 score·원관측 hash·독립 감사는 별도 증거다. 한 실제 run을 복제하여 두 반복으로 세거나 사후 정답이 실행 전에 동결됐다고 표현해서는 안 된다.

이 가드가 구현·독립 검증되는 조건으로 **최신 ADR 채택 동의를 유지한다**. 제품 후보 허용 집합 두 slot과 고객 확인/동의의 판단은 변하지 않는다. 모든 비교 후보·B0에 같은 교정을 적용하고, 원관측의 결정적 재채점·두 slot 외 의미 diff0·340ml 및 다른 실패 유지·현재/원래 runtime 일치·manifest-v4→v3 계보를 checker가 fail-closed로 검증해야 한다. 그 실행기 자체의 PASS를 본 정책 의견으로 대신하지 않는다.

미실행 보호v3의 최초1회, 최종 두 역할 실제 QA, UX 비교, G5·G6는 여전히 필수다. 앱/모델입력/보호 원문을 변경하지 않았다는 사실이 확인되지 않으면 이 재사용 근거는 성립하지 않는다. 현재 $20/2400 유지, 2500회 상한은 사용자 미응답이므로 승인된 것으로 취급하지 않는다. 이 부록은 예산/실제 GO나 재채점 결과 PASS가 아니며 추가 유료 호출·장부·코드·정답 변경0이다.
