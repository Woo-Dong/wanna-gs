# 원하GS 실행·시연·복구 안내

현재 구현·실험 중인 앱의 안내다. 최종 제출 URL과 G5/G6 통과는 아직 없으며 최신 판정은 [PROGRESS](../../PROGRESS.md)를 따른다. 이름은 원하GS, 발음은 ‘원하지쓰’다. 상품·공개 점포 위치의 참고 사실과 모의 가격·재고·발주·결제를 구분한다.

## 로컬 실행

저장소 루트에서 Node22·Python3.10 이상을 사용한다. `npm ci`, `npm run build`, `npm start` 순서로 production 빌드를 실행하거나 `npm run dev`로 개발한다. `.env.local`에는 사용자 OpenAI 서버 키·OPENAI_MODEL·LLM_MODE=live가 필요하다. 키 값과 보호 우회 비밀값은 Git·공유 문서에 넣지 않는다. `/api/health`의 configured는 설정 존재 여부이며 실제 모델 품질 통과 표시가 아니다.

`npm run gate`는 quality/gates.json의 현재 단계 검사·코드 지문·독립 리뷰 일치를 확인한다. 작업 중 context가 바뀌면 이전 리뷰가 stale로 거절되는 것이 정상이다. 실제 최종 출시 증거 검사와 로컬 단위 검사를 구분한다. 번들 Python 위치는 [작업 공간](README.md)에 연결된 실행 로그를 참고한다.

## 한 탭의 정상 흐름

1. 고객 화면의 자연어 입력이나 입력 예시로 상품을 찾는다. 예시 클릭은 문장만 채우며 모델 응답이나 구매 동의를 대신하지 않는다.
2. 모델이 제시한 정확한 상품·맛·크기와 미확인 조건을 읽고 고객이 상품을 선택한다. 수량·한 점포·모의 단가·총액을 확인하고 자동 모의 결제 및 수령 조건에 동의한 뒤 요청한다.
3. 같은 탭에서 경영주로 전환하고 요청 점포의 ‘수요·발주’에서 최신 수요를 검토한다. 상품별 고객 요청 상세는 읽기 전용이며 수량·가격·동의·접수 순번·발주 연결을 확인할 수 있다.
4. ‘이번에는 5만원 안에서만’ 등으로 변경안을 만들고 이번 검토안에 반영한다. 미래 자동발주 정책은 별도 정책 확인·승인을 거친다. 실제 발주에는 경영주의 묶음 승인이나 이미 승인한 정책이 필요하다.
5. ‘주문·픽업’에서 모의 공급량을 확정한다. 전량 확보와 유효 동의가 있으면 접수 순서에 따라 배정·모의 결제한다. 공급 확보와 입고는 별개다.
6. 확보한 상품의 입고를 기록한 뒤 고객 화면으로 돌아간다. 이때 생성된 픽업 알림 시각부터 정확히48시간의 수령 기한이 표시된다. 기한 안에 고객 또는 경영주가 수령을 기록한다.
7. 새로고침해 동일 브라우저에 저장된 상태가 복원되는지 확인한다. 다른 브라우저나 다른 배포 URL과 데이터를 공유하지 않는다.

## 예외 시연과 복구

경영주 화면 아래 ‘시연 도구’에는 정상 요청, 최소 발주 수량 미달, 공급 부족, 모의 결제 실패, 픽업 가능/만료의 합성 사례가 있다. 현재 시연을 초기화한다는 확인 후 준비하며 이 자료를 실제 모델 검색 성공으로 세지 않는다. 모의 시간은 앞으로만 이동한다. 예약 마감 시각을 가져와 정확한48시간 경계를 확인할 수 있다.

모델 오류가 나면 입력과 기존 요청은 유지된다. 모델 응답 실패를 미식별 니즈나 구매 성공으로 저장하지 않는다. 저장 결과가 불확실하면 화면의 ‘저장 결과 다시 확인’으로 같은 명령의 결과를 확인한다. 가격 변경이나 새 SKU 전환은 새 확인·동의가 필요하며 새 요청 성공 전 원요청을 임의로 없애지 않는다.

저장소 접근이 막히면 정상 브라우저의 저장소/WASM 접근 상태를 확인한다. 호환되지 않거나 손상된 저장 사본은 자동 삭제하지 않으며 화면의 명시적 초기화 동의 후 시작한다. 정상 reset도 현재 시연 초기화 체크박스와 버튼을 사용한다. 실제 로그인·공용 서버 거래 권한·여러 사용자 동시 경합을 구현한 서비스라고 주장하지 않는다.

## 증거와 작업 공간

정책 ADR·공개 보고서·PR/CI/배포 메타는 저장소에, 원본 응답·TAP·화면·SQLite 사본·실패 로그는 artifacts/raw 및 artifacts/private/run-20260921에 보존한다. 보호 holdout은 평가자만 접근한다. 이 경로가 Codex 전체 세션 원문의 완전한 사본이라고 주장하지 않으며 현재 Codex 작업과 기능별 worktree도 남겨둔다.
