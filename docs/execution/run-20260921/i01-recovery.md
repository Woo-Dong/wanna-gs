# I01 실제 연결 복구

목적: 정상 자연어 요청을 상품 확인·동의·보수적 발주·모의 결제·48시간 픽업으로 끝까지 연결한다. 실패를 숨기기 위해 호출 기록이나 거래 기능을 삭제하지 않는다.

## ModelUsage 저장 계약

root 자체 실제 브라우저에서 짜슐랭145g 요청의 실제 모델 응답은 올바른 기존 SKU와 live usage를 반환했지만 `agent.record`가 INVALID_INPUT을 반환하여 고객 후보가 표시되지 않았다. 독립 merchant-qa(research)도 예산 변경·복원 실제2호출 뒤 agent_runs=0으로 같은 결함을 확인했다. 기존 fixture는 토큰3필드만 사용해 이 연결 오류를 드러내지 못했다.

원인: API ModelUsage는 estimatedCostUsd를 포함하고, 도메인은 토큰3키만 허용했다. DBA가 estimatedCostUsd를 optional number|null로 허용하고 finite/nonnegative 검사를 추가한다. 사용량 미확인은 null로 유지하며 키/응답 원문을 로그에 기록하지 않는다. JSON 기록 구조를 유지하므로 schema/seed 번호를 변경하지 않는다. 고객·경영주 동일 영향 범위로 회귀한다.

경영주 화면은 저장 결과를 확인하기 전에 응답을 표시하고 실패를 무시하던 동작을 수정했다. 저장 성공·현재 scope/revision을 확인한 뒤 제안을 표시하며 실패 시 입력을 보존하고 다시 시도할 수 있게 안내한다.

초기 root 실패 원형: `artifacts/private/run-20260921/i01-own-live-smoke-failure1.json`. merchant 독립 모델2응답/SQL 근거는 해당 QA 보고서에 연결한다. 복구 결과는 새 실제 브라우저 실행·독립 QA에서 확인하며 이 문서만으로 PASS를 부여하지 않는다.

## 통합 화면

초기390px 실제 렌더에서 시연 설정·중복브랜드로 고객 입력이 화면 아래로 밀렸다. 역할 빠른 전환을 남기고 합성actor/점포 선택·상세 안내는 기본 접힌 details로 옮겼다. 고객 자체 브랜드/발음은 유지하고 공통 중복브랜드만 숨겼다. 초기/개선 스크린샷과 기본 역할 전환은 비공개 작업공간에 보존한다.

## 복구 실행 결과

사용량 계약수정 후 root 실제1호출로 고객상품확인→미체크동의→요청→경영주검토·묶음승인→공급·모의결제→입고·픽업·새로고침복원 PASS. root 테스트의 예약번호 locator가 설명문과 실제번호 두곳을찾던 오류는 하네스에서 범위를좁혔으며 제품결함으로세지않았다. 그 하네스실패도 private 원형으로보존했다. 최종실행은 i01-own-live-smoke.json, 독립경영주는 i01-merchant-browser.md를참조한다. 고객독립QA는별도보고서에서판정한다.

## CI 테스트 수집

I01 독립 CI 검사에서 총합만>0이면 필수 Python suite/Node glob 하나가없어도통과하는두반례를발견했다. 각필수디렉터리·glob의매치/테스트건수를검사하도록수정했고독립6반례/정상Python91+Node44 통과를확인했다. tests/**/*.html 지문누락도보완했다. 이CI결과는해당단위·빌드범위이며실제브라우저/모델전체품질과구분한다.
