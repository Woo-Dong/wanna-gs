## 목적과 정상 흐름

경영주가 명시한 수량 제한을 지속 정책 저장 과정에서 버리지 않는 보완이다. 한 정책 확인 화면에서 예산·범위·수량 상한을 함께 승인하고, 이후 개별 SKU마다 추가 승인받지 않으므로 기존 업무 감소 목적을 유지한다. 고객 요청 수량이나 모집 상한으로 전용하지 않고 실제 수요를 그대로 남기는 점이 D-41 및 CORE-25와 일치한다.

새 검토 이벤트마다 상한을 적용하는 것은 일일 누적 상한과 다르다. 본문이 이 차이와 미지원 일일/주간 조건의 명확화 요구를 명시하고 있어 정책상 차단 반례는 없다. 화면 확인에서는 단순 “상품별3개”만 보여주면 안 되고 “검토 한 번마다 각 상품 최대3개, 다음 새 검토에서도 추가 발주 가능”이라는 의미가 보여야 한다. 이는 새 기능 요구가 아니라 제안한 단위의 구현 검증 사항이다.

## 채택 후 필요한 확인

정책·domain 타입/저장·모델 정규화·확인 UI·eval oracle을 함께 갱신한다. 미지원 unknown constraint를 무시하지 않는 실행 반례, 명시 전체 조건 저장, 한 이벤트당 단일 검토, 다음 외부 이벤트의 정상 추가 발주, MOQ보류와 null 회귀를 실제로 검증해야 한다. 이 보고서는 그 실행 PASS를 대신하지 않는다.
