# N02 자연어 개선 실행 기록

목적: 존재하는 정확한 상품 후보를 고객의 확인·동의로 연결하고, 경영주의 명확한 조건을 현재 묶음과 지속 정책에 정확히 반영한다. 모호·미식별·대체·추가 조건은 불확실성을 보존한다. 정상 입력을 모두 거절하거나 기준을 낮춰 실패를 없애지 않는다.

기준: ADR003의 고정 공개 dev252/validation84, 최종 보호 holdout84, 역할별 출시 최소와 필수 오류0, 서로 다른 best validation 두 실행, 후보 한도·동일 비교·정체 중단. 구현자 root와 평가자 method_auditor 분리. 보호 내용·정답·생성기는 root/실험자에게 제공하지 않는다.

## 기준선 B0

- source `10c00723d0b64ea47a06dcbd00e2b671e7c62daf`, I01 Preview `dpl_73afciHs7CadEfeNSzpzz86sRmXz`, prompt baseline-v1, gpt-5-mini-2025-08-07.
- config/상태/실행기/source 및 READY 배포 기록을 고정하고 공개336case/368turn을 실제 실행 중. 실패도 분모·사용량에 포함한다. 결과는 완료 후 독립 scorer로 확정한다.
- 초기 관측: 이름이 비슷한 다른 맛/규격의 SKU가 반환된 공개 사례가 있다. 일부 INVALID_MODEL_RESPONSE는 원모델 출력이 없어 구체 원인을 단정하지 않는다. 전체248상품 입력에 정답이 있는데도 반환한 SKU가 달랐다는 사실과 긴 입력에서 속성/ID 결합이 약해질 수 있다는 가설을 구분한다.

## 후보 C1 사전 가설 — 아직 실제 모델 미실행/미채택

- 카탈로그의 이름·별칭을 NFKC/문자 정규화하여 전체 이름의 명시적 언급이 있으면 관련24개를 우선 제공한다. 약한 bigram 유사도만 있을 때에는 전체248을 유지하고 순서만 조정한다.
- 대화에서 실제 언급한 이전 SKU는 후보 집합에 보존한다. 최신 정정·부정·추가 조건은 모델이 모두 판단하며, 이름 일치가 exact 판정이나 동의를 강제하지 않는다.
- 후보 ID와 경영주 SKU/상품군을 전달한 실제 카탈로그의 enum으로 구조화 출력에 제한하는 가설을 함께 검토한다. 기존 서버 검증과 앱 확인·동의는 유지한다.
- 비공개 작업 영역의 순수 검색 prototype에서 전체248개 정확명 회수248/248, 공개 customer-dev180개 required SKU 회수 누락0(143개만 축소), 정규화·약한 근거 fallback·이전SKU 보존 검사 PASS. 이는 카탈로그 검색 회수 검사이며 모델 정확도·latency·UX·출시 합격 증거가 아니다. validation으로 알고리즘을 조정하거나 holdout을 읽지 않았다.
- [독립 가설 검토](n02-retrieval-review.md). baseline 서버는 변경하지 않고, 완료 후 후보를 별도 배포하여 한도 안의 dev 검사와 고정 validation으로 비교한다.
