# C5 실행 전 예산·진행 조건 독립 감사

판정: **현재 고정 계획에서는 C5 dev 첫 호출 전 COST_SOFT_STOP 조건이 참이다. 실제 실행 금지 유지**. 이는 예산 장부와 실행기 분기 읽기·산술 검토 결과이며 실제 provider 호출이나 Budget.reserve 실행 결과로 가장하지 않는다. 장부 쓰기·새 attempt·실제 모델·보호 holdout 접근은 모두0이다. 비실행 기술 수정·mock 회귀는 별도로 계속할 수 있다.

## 새 장부 증거

읽은 파일은 `artifacts/private/run-20260921/nl-budget.json`, SHA `9b4ff740edfb5be0aa2cea4edaa4c2f61c8b7fafc717a1f6c5247dcd82616cf7`이다. 읽기 전후 바이트 hash가 같음을 확인했다. known provider calls703, unknown0, pending0, prior call reserve50로 **upper753회**다. 측정 추정비용$3.2195333 + prior 비용 예약$2.50 = **upper$5.7195333**이다. prior 비용은 실측이나 공급자 청구 확정액이 아니다.

| 첫 attempt 검사 구성 | 금액/수량 |
|---|---:|
| 현재 누적 비용 상계 |$5.7195333|
| C5 dev 뒤 필수960attempt × $0.0105 |$10.0800000|
| 다음 attempt unknown 예약 |$0.0500000|
| 비용 비교 합계 |**$15.8495333**|
| $15 초과액 |**$0.8495333**|

`scripts/run_nl_eval.py`의 Budget.reserve는 `누적 + unknown 예약 + 미래 비용 >= 15`이면 pending attempt를 만들기 전에 COST_SOFT_STOP을 반환한다. Runner는 reserve가 성공해야 transport.post를 실행한다. 현재 값은 경계와 같아도 중단하는 비교를 이미 초과한다. 소수점 표현의 극소 오차를 제외해도 판정은 달라지지 않는다.

호출 수 조건은 별개다. 고정 dev34발화의 최대3attempt=102를 현재 실행 몫으로 보존하면 `753 + 102 + 960 = 1815 <= 2400`이므로 호출 수 상한은 첫 차단 원인이 아니다. 남은 nominal 비용 $9.2804667만 보고 실행 가능이라 판단하면 미래 필수예약과 unknown 예약을 누락한다.

## 실패한 이전 평가를 공제할 수 없는 이유

C4 validation은 같은 source/config로 첫84/84, 둘째83/84였고 후자는 경영주 불확실8/9로 최소90%에 미달했다. 두 번째 실패·비용·분모 및 repeat_ready=false를 [평가 보고서](n05-c4-validation-evaluation.md)에 보존했다.

C5는 stale 상태에서 모델 출력 schema를 제한하는 다른 후보다. 실제 모델 응답 후 결과를 교체하지 않는 설계 여부는 별도 기술 검토 대상이며, 설계만으로 C4 성공을 C5 검증으로 재분류할 수 없다. C5의 source/schema가 바뀌므로 C5에는 동일 설정의 validation84/92발화 **두 번**, 각각 독립 최소 기준 통과가 다시 필요하다. C4에서 이미 쓴184회는 goal 비용에 남고 C5의 미래552attempt 예약을 줄이지 않는다. 최종 holdout276, best UX72, G5/G6 60과 합쳐960을 유지한다.

현재 단계는 dev이므로 이전 C4 validation config의 미래684/$7.182를 그대로 사용하면 C5 첫 validation 한 묶음을 무단 공제하는 오류다. 684로의 전환은 새 후보가 dev를 통과해 실제 첫 validation을 실행할 때 그 현재 실행분을 분리하는 사전 계획에만 해당한다. 지금은 해당 조건이 성립하지 않는다.

## 진행 필요조건과 금지된 우회

현재 비용 계획 그대로라면 첫 attempt를 허용하려면 비교 합계가 **$15 미만**이어야 한다. 현재 부족액$0.8495333만 정확히 해소해 합계가$15가 되어도 `>=` 조건 때문에 여전히 중단이다. dev 실제 비용 여유까지 확보하려면 더 큰 차이가 필요하다. 이 산술은 한도 증액이나 예약 축소의 승인 제안이 아니다.

이번 감사는 $15·회당$0.0105·필수 횟수·prior50·unknown$.05를 변경하지 않는다. 실패를 본 뒤 두 반복을 하나로 줄이거나, C4를 C5의 반복으로 재사용하거나, 불확실 사용량을0으로 적거나, 새 장부/후보 이름으로 지출을 초기화하지 않는다. 명시된 현재 제약을 유지한 한 C5 live는 계속 차단 상태다. 실행 조건을 바꾸려면 별도 정당한 권한과 사전 계약·독립 검토·동결 증거가 필요하며, 본 문서는 그 변경을 수행하거나 승인하지 않는다.

## 비용과 독립적인 최종 블로커

CORE-25의 UX 편의성 비교는 별도로 **NOT_READY**다. ADR006의 B0 최초24는2PASS/1FAIL/21미실행, 단일 복구24는11PASS/1FAIL/12미실행이다. [원본 분모](ux-baseline-recovery-results.md)를 유지하며 성공 조각을 합치거나 C5를 새로운 B0로 바꾸어 상대 비교를 통과시킬 수 없다. ADR006은 세 번째 자동 실행을 허용하지 않는다.

따라서 예산 문제를 해결했다고 해도 이 UX 비교와 best 미선정·보호 holdout·최종 G5/G6가 자동 해소되지 않는다. 선택 실험 중단은 필수 품질 면제가 아니다. C4/C5 비실행 기술 준비, 실패 원인 재현, 문서·제출 접근 계획 및 기존 상태 증거 보존은 실제 모델 호출 없이 계속할 수 있지만 최종 목표 완료로 선언할 수 없다.
