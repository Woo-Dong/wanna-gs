# C6 한도 종료·제한 재개 제안의 독립 평가 검토

판정: **현재 추가 후보·유료 평가 실행 권한 없음. 사용자 새 지시를 전제로 한 고객 전용 한 후보 제안은 조건부 타당하나 아직 미승인이다.** C6 dev29/30·고객 불확실6/7·기존 정상 회귀1을 FAIL로 유지한다. C6 재실행이나 validation 진입으로 이 실패를 덮을 수 없다. 앱·모델 호출·장부 변경·보호 원문 열람0인 문서/메타데이터 검토다.

## 현재 종료 근거

[23번](../../23-nl-experiment-loop.md)의 빠른 선별은 실패 후보를 비싼 전체 live 평가로 보내지 않도록 한다. ‘고객/경영주 각각 … 최대6개 후보, 전체 최대12개’와 ‘더 나은 새 가설이 있어도 이번 목표의 한도를 자동 연장하지 않는다’, ‘사용자 새 지시가 있으면 별도 범위를 정한다’가 적용된다. [ADR003](../../decisions/ADR-003-evaluation-and-demo-boundaries.md)의 채택된 개선·중단 행도6/12와 핵심범주·필수 정상 회귀0을 규정한다. [C6 계약](c6-recovery-plan.md)은 각 역할 여섯 번째/마지막, 슬롯 초기화 없음과 새 holdout 실패 후 C7 자동 시작 금지를 명시한다.

따라서 미지정 세부 정책을 해결하는17번의 자율 ADR 절차로 이미 소진한 후보 한도를 다시 열 수 없다. ‘버그 복구’, 새 task 이름, 모델 변경, 고객만 시험하는 새 실험 이름으로 재분류해 우회할 수도 없다. 필수 품질 미달 상태라는 이유는 무제한 후보 허가가 아니다. 지금 결과는 `rejected-regression`과 `candidate-limit`이며 비용 소진이나 접근 장애가 원인은 아니다.

C5는 validation 최소를 만족했어도 최종 holdout82/84·경영주 명확14/15 미달이어서 출시 가능한 최선 버전이 아니다. C6 기각 후 보존된 이전 소스로 돌아가는 것만으로 goal이 달성되지 않는다. 추가 자연어 최적화를 멈추되 가능한 무호출 문서·원본 보존·기술 검토는 계속할 수 있으며, 최종 G5/G6 완료를 선언할 수 없다. D46은 비용20과 UX 재설계 승인으로, 후보 수 자동 연장 승인이 아니다.

## 제안 범위: customer7 / merchant6 / 합계13

현재 새 실패는 고객 미등록 요청에 다른 실존 상품을 exact로 추천한 인접 정상 회귀다. 그러므로 사용자에게 제안할 최소 범위는 **고객 역할에 추가 한 후보만 허용**하는 것이다. C6 경영주 동작을 그대로 두면 customer7/merchant6, 역할별 합계13으로 충분하다. 새 통합 배포/두 역할 평가를 한다는 이유로 경영주 후보를 자동으로7로 올릴 필요는 없다. 7/14는 두 역할 모두를 실제 변경하고 그 범위를 사용자가 별도로 승인하는 경우에만 맞는 표현이다.

고객 전용의 의미 경계는 사전에 적는다. 고객 prompt/schema/판정에 한정하며 경영주 prompt·검색·schema·mapping·provider/model·업무 의미의 변경을 포함하지 않는다. 공통 파일을 수정하더라도 경영주 경로가 의미상 불변임을 diff·독립 정상/반례·실제 두 역할 평가로 확인해야 한다. 공통 모델·provider·catalog/search 변경처럼 두 역할 행동을 바꾸는 변경은 이 고객 전용 승인에 포함되지 않는다. 실제 영향이 두 역할이면 구현 중 자동 확장하지 않고 별도 범위를 판정한다.

승인 전에는 고객7번째 후보 구현/실제 호출을 시작하지 않는다. 승인되면 사용자 직접 변경을 원장·ADR의 대체 범위·인덱스·context·후보 원장·실행 config에 기록한다. 과거6/12 계약과 C1~6의 원본/실패/비용은 역사적 증거로 그대로 둔다. 허용은 한 후보이며 실패 뒤 C8·같은 후보 재실행·추가 holdout·새 장부를 자동 생성하지 않는다.

## 유지해야 할 실행·판정 조건

1. 동일 고정 dev30/34turn과 원래 공개 정답·scorer·회귀를 사용한다. 추가 후보의 기술 독립 검토와 G1~G4를 먼저 수행하고 exact PR/CI/Preview/source 결속을 확인한다. 선별에서 최소/정상 회귀를 실패하면 이후 live를 진행하지 않는다.
2. 두 역할 전체 validation84/92turn을 동일 모델·소스·prompt·dataset·state·설정으로 독립 run ID 두 번 실행한다. 각각95/90/mandatory0 및 원래 정상 경로 조건을 만족해야 한다. B0 paired 오류 감소와 정상 회귀0, C5 repeat01↔01·02↔02의 핵심범주/필수 정상 회귀를 원래처럼 공개한다. C6 실패도 비교에서 숨기지 않는다. 좋은 repeat 선택/합산/정답 수정은 금지한다.
3. 통과한 버전을 최종 동결한 뒤 이미 데이터 검토 PASS로 동결된 새 보호84를 **최초 한 번** 실행한다. 원래 C5 holdout은 재호출하지 않는다. 현재 새 dataset hash `18f2a373dc48b372f166e6dd6f51fd97687a406e33f8f601fe814bbeafd6c305`는 장부 claim이 없고 앱 구현자에게 원문/정답이 노출되지 않았다. 승인 후보가 달라진다는 이유로 새 문제를 다시 생성하지 않는다. manifest의 역사적 revision명 `holdout-v2-c6`와 승인 후보의 관계를 문서화하되 보호 정답/hash/분모를 바꾸지 않는다. 아직 실제 품질 PASS가 아니다.
4. NL 통과 뒤 ADR007 한 번의 UX v3 양 arm·best56/56·baseline workload별 정상≥3·조건부 시간/최대조작 기준, 독립 두 역할 실제 브라우저 QA·정책/운영 검토·G5·제출 URL G6를 모두 수행한다. 과거 UX 실패와 새 v3 not_run을 보존한다. NL 통과가 UX 또는 최종 배포 성공을 보장하지 않는다.
5. 각 단계 실패는 원본과 전체 분모에 남긴다. 원래 NL timeout/429 최초포함≤3 계약과 auth/quota/pending 중단, UX retry0/unknown usage STOP을 구별해 그대로 적용한다. 새 후보에 대한 실패 뒤 추가 자동 반복0이다. $20/2400, prior50, 기존 unknown 비용, 미래 필수 예약과 단일 장부를 유지한다.

### 같은 validation 설정의 보수적 중복 예약

위 총합과 **현재 실행기 config의 보수적인 중복 예약**은 구별한다. 기존 방식처럼 두 validation에 동일 config의 미래708(두 번째276+holdout276+UX96+G5/G660), 비용$7.434를 계속 유지하면 두 번째 반복 중에도 자기 반복분276이 보수적으로 남는다. 동일 config fingerprint 요구 때문에 실행 중 임의로432로 줄여서는 안 된다.

dev102·첫 validation276·둘째276이 모두 최대로 소진되는 경계에서는 둘째 종료 무렵 guard 계산이1098+102+276+276+708=2460이어서2400보다60회 크다. 현재 코드 조건에 따르면 둘째에 허용되는 추가 호출은 최대216회이므로 나머지60회 전 `CALL_RESERVE_STOP`이 가능하다. 같은 추정 단가로 그 지점의 비용 guard 합은$21.7113041로20보다$1.7113041 크며 비용이 먼저 막을 수도 있다. 반면 정상34/92/92 경로는 이런 중복 예약을 유지해도 여유가 있다.

따라서 **현재 기구를 유지한 제한 후보 제안은 정상 예상 경로에서 가능하지만 모든 허용 재시도 경계까지 완주를 보장하지 않는다.** 이 한계를 사용자에게 숨기지 말고 기존 중단을 유지하면 기준 완화 없이 제안할 수 있다. 최악 재시도 전량까지 예약 가능하다고 주장하려면, 현재 반복과 진짜 미래 필수를 구별하는 사전 고정 reserve schedule·동일 설정 결속에 대한 별도 기구 설계/독립 검토가 먼저 필요하다. 이번 검토는 그 변경을 승인하거나 구현하지 않았고, $20/2400 인상·필수 예약 누락으로 해결할 것을 권고하지 않는다.

## 현재 상태

제안은 미승인, 추가 후보/실제 호출/장부 쓰기0이다. 조건부 검토가 새 정책 채택이나 사용자 동의가 아니다. 승인 후에도 단계별 실증 결과가 부족하면 NOT_READY를 유지하며 모든 로그·작업 공간·원본을 남긴다.
