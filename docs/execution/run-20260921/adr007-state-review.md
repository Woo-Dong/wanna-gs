# ADR-007 측정·상태 독립 검토

판정: **초안 채택에 동의, 실행 장치·실제 연구는 미검증**. 검토한 최종 초안 SHA는 `7334ff761f47b697518051b771df85a2a6c57ffb024647596daa6d013b890e72`다. 제안자 root와 독립인 method_auditor가 D-46 사용자 승인, ADR003/006, CORE17/18/21/25와 대조했다. 다른 검토자의 결론을 읽어 따르지 않았으며 조정자가 전달한 STOP 우선·실제56시도 보완의 현재 원문을 직접 확인했다. 정책 본문 수정·새 모델 호출·장부 쓰기·holdout 접근0이다.

## 권한·목적 보존 판단

D-46은 실패 이력과 최종 제품 품질을 유지한 UX 복구·비교 재설계를 두 독립 검토로 허용했다. 새 초안은 baseline을 출시 가능한 제품으로 승인하는 대신 실패도 존재하는 비교 대상으로 정의한다. best의56/56 최초 정상, 절대조작/질문 한도, SQL·동의·수량·금액·48시간, relative 조작 증가0·비모델 중앙값10% 한도는 유지한다. 사용자 권한을 제품 고객/경영주의 동의·실행 승인으로 대체하지 않는다.

기존3회 arm 및 ADR006의 baseline 전체24PASS 조건을 새 study에 한해서7회 arm/정상 최소3개로 바꾸는 대체 관계가 명시돼 있다. 과거48계획·13PASS/2FAIL/33미실행과 NOT_READY는 바뀌지 않는다. 이를 단순 문서 오탈자 수정으로 취급하거나 옛 연구 결과에 소급 적용하지 않는다.

## 비교와 분모

한 연구·고정 run ID·8 workload×7회·같은 기구/순서/seed/clock/viewport는 결과를 본 뒤 성공 회차를 선택할 여지를 제한한다. 매 workload에서 baseline 정상3~7개 모두와 best7개 모두를 비교하고 조작/이동 최댓값과 비모델 시간 중앙값을 계산한다. baseline 성공 수가 다를 수 있으므로 이 지표는 **동일 정상 경로를 완료한 조건에서의 자동화된 편의성**만 의미한다. 전체 요청의 무조건 완료시간, 인간 사고시간, 통계적 유의성·일반 사용자 모집단의 신뢰구간을 증명하지 않는다. 본문이 이 해석 한계를 명시한 점은 적절하다.

baseline의 실패를 느린 값 또는0으로 대입하지 않고 별도 전체 분모에 남긴다. 성공 경로만 비교하는 선택 편향을 없앤 설계라고 주장해서는 안 되지만, 최종 best56/56과 별도 NL/holdout 기준을 유지하므로 실패한 baseline을 정상 기준으로 위장하지 않는다. 새로운 성공 결과를 일부만 골라 편의성 수치를 높이는 방식도 금지돼 있다.

## 비용·출처·구현 전제

명확3×7=21, 모호2×7=14, 자동정책7로 정상 arm당42모델 발화, 두 arm84회라는 산술은 기존8 workload의 호출 경로와 맞는다. 추가12회는 예약 여유로만 쓰며 새 trial·재시도 권한이 아니다. 실제 실패로 호출이 줄어도 planned/attempted/후속 NOT_RUN을 보존한다. 새 candidate의96 UX 예약은 이전72 예약과 다르므로 다음 동결 config는 이를 반영해야 한다. $20·2400·prior50·unknown$.05·다른 필수 후속예약을 줄이지 않는다.

연구 시작 전 두 arm의 source/model/prompt/catalog/schema/runtime, 동일 v3 기구·고정 순서/준비와 budget-root를 결속해야 한다. B0 source10c0072를 현재 candidate로 치환하지 않고, best는 최종 NL 검증 뒤 동결해야 한다. UI/domain/seed 차이는 원문 계약대로 실행 전 확인·기록한다. 실제 측정기·metrics·release checker는 전부 같은 정책을 적용하고 stop/null/pending/시도분모/고유trial/최소정상수/56best정상·행동/시간 기준을 raw에서 검사해야 한다.

현재 v2 기구가 이 정책을 이미 지원한다고 주장하지 않는다. 새 구현에 정상/경계·기존 실패 보존·모의/live·원본hash·새 source stale 검사와 독립 검증을 요구한 초안 조항을 유지한다. 구현자 자체 PASS는 독립 검증이 아니다.

## 결론

위 최종 초안은 사용자 승인 범위의 제한된 새 비교 절차이며 최종 제품 정상 기준을 면제하지 않는다. 측정/상태 관점 채택에 동의한다. 후속 구현 검증과 두 arm 실제 완료 전까지 UX 비교는 여전히 NOT_READY이고, C5 기술 PASS나 예산20 변경으로 이 상태를 바꾸지 않는다. 새 study 실패 시 자동 추가 study를 시작할 권한도 없다.
