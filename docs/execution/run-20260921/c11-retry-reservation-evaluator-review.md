# C11 재시도·후속 예약 독립 평가 검토

- 검토자: method_auditor. 후보 앱 구현자와 분리. 기존 평가 실행기 작성 이력이 있으므로 이번 판정은 계약·예약 산술 검토이며 새 실행기 구현의 독립 PASS를 대신하지 않는다.
- 판정: **조건부 허용**. C11 전체 NL 단계에 `max_attempts=1`을 실행 전에 고정하는 것은 ADR003의 ‘429/timeout 최초 포함 최대3회’라는 상한 안의 선택이다. 현재 구현은 3회 고정이므로 이 문서만으로 실행하지 않는다. 기본값3의 과거 계약·결과를 보존하고 아래 변경을 독립 검증해야 한다.
- 목적 보존: 정상 자연어의 정확한 후보·동작, 모호/미식별 보존과 고객 확인을 유지한다. 선택적 재시도를 제거할 뿐 필수 사례·대화·독립 평가·출시 품질을 제거하지 않는다. D48은 증거 있는 복구 판단 권한이며 $20/2400회 또는 정답/분모/최소 기준 면제 권한이 아니다.

## 확인한 실제 장부와 산술

운영 장부 SHA-256 `7cfce2906a5e56814e65614eb9a4657504316a1426e5ccf3d45aaf172eb60fad`, upper1786회/$11.0094737, known1736회/$8.4594737. prior50회/$2.50은 실측이 아니며 기존 unknown usage $.05를 유지한다. 남은 상한은614회/$8.9905263이다.

|---|---:|---:|---:|---:|
| dev30/34turn |1786|34|372 = validation184 + holdout92 + UX84 + QA/G6 12|2192|
| validation01 84/92turn |1820|92|280 = 다음 validation92 + holdout92 + UX/QA/G6 96|2192|
| validation02 동일 config |1912|92|280, 첫 반복과 같게 유지|2284|
| 신규 holdout 최초84/92turn |2004|92|96 = UX84 + QA/G6 12|2192|

실제 계획 최대 호출은34+184+92+84+12=406회, 누적2192회다. 동일 validation 설정의 보수적 중복 예약 때문에 두 번째 validation 진입 총량은2284회로 더 크지만2400 이하이다. 남은208회를 추가 실험 권한으로 부여하지 않는다. 모든 단계가 정상적으로 성공한다는 조건의 계획이며 오류·불확실성·비용 STOP을 없애지 않는다.

후속 비용 예약은 dev $3.906, validation $2.940, holdout $1.008(호출당 $.0105 운영 추정)이다. 현재 비용 + 계획406회 추정 + 다음 unknown $.05 = **$15.3224737**. 실제 token 비용의 최악 상한이나 공급자 청구 보장은 아니다. 각 호출 직전 실제 누적 비용과 미래 예약을 계속 검사한다.

## 비호출 임시 검사 증거

기존 `Budget.reserve`를 임시 장부 사본에만 사용했다. 운영 장부를 읽은 전후 바이트와 해시가 동일하다. 진행 단계의 추가 호출/비용은 명시적인 합성 레코드이며 실제 실행 결과가 아니다.

- 위4개 단계의 제안 산술 PASS.
- 같은 val02에 기존 현재단계 3회 예약을 적용하면1912+276+280=2468로 `CALL_RESERVE_STOP`임을 확인했다. config만 추가하고 기존 반복/예약 코드를 두는 구현은 실행 가능하지 않다.
- 총2400 허용,2401 중단 및 비용20 도달 경계 중단을 확인했다. 총8검사 PASS.
- private 증거: `artifacts/private/run-20260921/c11-reserve-review/{probe.py,results.json}`. 모델/HTTP0, 운영 장부 쓰기0. 새 retry 구현 시험은 **not_run**.

## 반드시 함께 결속할 구현 범위

1. 선택 필드 `max_attempts`는 생략 시3, 명시 시 boolean을 제외한 정수1~3만 허용한다. 0/4/null/문자열/실수는 실행 전 거절한다. 기존 config나 기록에 새 필드를 삽입해 옛 hash를 바꾸지 않는다.
2. `retry_range`, 현재 단계 `remaining * max_attempts` 예약, 마지막 재시도 종료 조건을 같은 유효값에 연결한다. SDK 자동 재시도는 늘리지 않는다. max1의 timeout/429는 한 번 실패로 보존하며 성공으로 바꾸거나 분모에서 제외하지 않는다. 뒤 user turn이 미실행이면 incomplete/전체 실패 분모도 유지한다.
3. 현재 config 전체를 포함하는 run fingerprint를 유지해 resume 중1→3 변경을 거절한다. pending 불확실 호출은 재실행하지 않는다. 이미1회 시도한 current_attempt가 있는 resume에서 추가 호출이 없어야 한다. 완료 결과를 새 run으로 바꿔 선택적으로 재호출하는 권한은 없다.
4. validation 두 반복은 같은 config·동일84사례/92turn·서로 다른 실제 run ID다. holdout의 validation-config 비교는 현재 `CANDIDATE_KEYS`에 max_attempts가 없으므로 **유효값(생략3)을 별도로 대조**해야 한다. validation1→holdout3 전환을 거절하고 생략3↔명시3의 의미적 동등성은 명확히 처리한다. 동결 best/증거에서도 이 실행 조건을 확인 가능하게 남긴다.
5. 기존 STOP, usage/비용/전체 시도, 최초 성공률, 전체 요청/응답 분모, 안전 불변식을 바꾸지 않는다. max1이 일시 장애 내성을 낮췄음을 비교 보고에 명시한다. 과거 max3 결과를 새 max1 결과라고 재표시하지 않는다. 고정 C5 대응 핵심범주·필수정상 회귀0, B0 paired 개선, 역할별95/90, 각 repeat 불완전0·mandatory0 모두 유지한다.

필요한 mock 회귀는 생략3 기존 동작, 명시1 정상 성공, 429/timeout의 정확히1회 실패, 다턴 후속 미실행 보존, 소진한 attempt의 resume0회, pending resume 거절, 잘못된 max 형식, config 변경 resume 거절, validation/holdout max 불일치 거절, 동일 유효3 정상 경로, 위 예약 경계다. 본 검토자가 작성한 실행기 변경을 자기 시험으로 독립 검증이라 부르지 않으며 별도 검토자 증거가 필요하다.

## 보호 평가와 진행 경계

C10 validation84/84 두 번은 보존하지만 holdout-v2 76/84, 고객 uncertain12/20(60%) FAIL이다. 이를 새 성공으로 바꾸지 않는다. 역할 QA/UX/G5/G6는 아직 완료되지 않았다.

C11을 평가하려면 독립 신규 holdout-v3 84사례/92turn, 고객60/경영주24, clear40+15/uncertain20+9,18범주·동등 난도를 유지해야 한다. 공개 dev/validation/demo 및 은퇴 holdout-v1·사용한 v2와 의미 family 비중복을 독립 검토한다. 상품명·숫자·말투 치환은 새 family 근거가 아니다. 원래 manifest/v2/실패/claim을 보존하고 revision 계보·정답 검토·source/state/hash를 결속한다. 데이터 제작/검토는 모델 호출이 아니며 별도 최초 실행 권한을 뜻하지 않는다.

본 판정은 자원 설계의 조건부 적합성이다. 후보 기술 검증, 재시도 실행기 독립 검증, 신규 보호 데이터 독립 검토, 정확 배포/소스 결속과 root의 단계별 GO가 실제 실행의 선행조건이다.

## 후속 비용예약 보강 검토

조정자가 두 번째 독립 검토의 보수 제안을 반영해 비용예약을 변경했다. 위 $.0105×전체호출 산술은 당시 제안 검토로 보존하고, 실행용 비용예약은 **NL 후속 turn당 $.0105 + UI/QA96회×$.05=$4.80**으로 강화한다. 호출 예약372/280/96과 전체2400·$20은 그대로다.

- dev 후속276 NL turn + UI/QA96: **$7.698**, 현재11.0094737 + 다음unknown.05 +7.698 = **$18.7574737**.
- 동일 validation config의 후속184 NL turn + UI/QA96: **$6.732**. 정상 dev34+val01 92를 모두 $.0105로 추정한 val02 진입 비용 검사값은 **$19.1144737**다.
- holdout 후속 UI/QA96: **$4.80**.

계획 전체310 NL turn +96 UI/QA 호출을 각각 위 추정으로 계산하면 현재누적+예상+다음unknown = **$19.1144737**. 실제NL 호출비용이 추정을 넘거나 새로운 불확실 사용량이 생기면 미래 예약을 침해하기 전에 기존 soft STOP이 걸릴 수 있다. 모든 호출 완주나 최종 PASS 보장은 아니며 추가 자금/호출 권한은 없다. 이 더 큰 실행 예약에도 동의한다. 기존 Budget 경계검사는 그대로 유효하고 새 config/실행기 검증은 별도다.
