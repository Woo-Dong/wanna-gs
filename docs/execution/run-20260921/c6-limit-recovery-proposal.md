# C6 한도 도달 후 고객 전용 복구 제안

상태: **D47 사용자 직접 승인으로 고객 후보 하나 실행 허용**. 아래는 승인 전에 검토한 범위이며, 질문에 대한 실제 답변은 ‘고객 후보 1개 추가 승인’이다. 독립 검토 문서의 미승인 표시는 각 검토 당시 상태로 보존한다. 기존 D46은 비용 $20 및 UX 복구만 승인했으며 후보 한도 연장을 포함하지 않는다. 현재 C6 dev29/30 FAIL과 출시 적격 best 부재를 보존한다.

제안은 고객 복구 후보 하나만 추가해 고객7/경영주6, 총13으로 제한하는 것이다. 공개 C05 회귀인 미등록 상품·대체 거절의 잘못된 exact 추천을 다루되 정상 상품의 정확/별칭/모호/대체 허용·거절/정정 흐름을 함께 검증한다. 고객 전용 prompt/schema/분기만 최소 수정하며 모델·catalog·공통 packing/retrieval·경영주 동작·거래 도메인은 유지한다. 정답·case명 하드코딩, 출력 사후 교체, 전부 거절은 허용하지 않는다. 구체적인 구현 가설과 변경 diff는 승인 후 독립 기술 검토한다.

기존 실패·정답·분모·95/90·mandatory0·정상 회귀0·B0 및 C5 고정 비교 기준을 유지한다. 같은 dev30→같은 validation84 두 번→source 동결→미실행 신규 holdout84 최초 한 번→ADR007 UX 양 arm·독립 역할 QA→G5→main/Production→제출 URL G6를 순서대로 수행한다. 각 선행 기준을 통과한 경우에만 다음 유료 단계로 진행한다. 은퇴한 기존 holdout은 재호출하지 않는다. 추가 후보가 필수 단계에서 실패하면 자동 후보 추가나 평가 재실행을 하지 않는다.

비용 $20/2400회와 공유 장부·기존 prior50/unknown예약을 유지한다. 현재 upper1098/$7.3603041에 추가 dev최대102와 후속984의 실제 필요 예약을 합하면2184회/$18.8133041(다음unknown$.05 포함)이다. 이는 계획 추정이고 최악 청구액이나 완주 보장이 아니다. 기존 실행기의 보수적 중복 예약·실제 retry/토큰이 중단 조건에 걸리면 그대로 멈춘다. 구매·자동 충전·한도 우회는 없다.

[제품 독립 검토](c6-limit-recovery-product-review.md)와 [평가 독립 검토](c6-limit-recovery-evaluator-review.md)를 함께 읽는다. 독립 검토는 제안의 타당성 평가이며 사용자 승인을 대체하지 않는다. 사용자 새 지시가 오기 전 앱 수정·새 후보·모델 호출을 시작하지 않는다.

근거: [23번](../../23-nl-experiment-loop.md)은 “더 나은 새 가설이 있어도 이번 목표의 한도를 자동 연장하지 않는다”라고 규정한다. [자연어 실험 스킬](../../../.agents/skills/wanna-gs-nl-experiment/SKILL.md)은 “유료 구매나 한도 확장은 별도 권한 없이 실행하지 않는다”라고 규정한다. 이번 질문은 새 제품 정책을 사용자에게 위임하는 것이 아니라 이미 채택한 실험 시도 한도 변경을 확인하는 것이다.
