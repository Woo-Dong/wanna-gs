### EP-01 — baseline의 ‘모든 case’에서 final holdout 제외

현재 반복 항목은 ‘모든 case 기준선1회’, 비용은 ‘baseline420’으로 되어 있어 보호 holdout84도 후보 생성 전에 실행할 수 있다. 정확 발화를 비공개로 둬도 holdout 점수/실패 분석을 먼저 보고 후보를 고르면 최종 독립 평가의 의미가 약해진다. 독립 평가자만 baseline holdout을 실행해 밀봉하는 방법도 가능하지만 이번 데모의 더 단순한 계약은 **baseline=dev+validation, holdout은 best 고정 후 최초 실행**이다. 420은 전체 dataset 수이고 초기 baseline 호출 수는 336(분할 오차 반영 실제값)으로 구별한다. 구현자/실험자에게 final holdout의 정확 발화·정답·case별 결과를 사전 전달하지 않는다. final 실패를 튜닝에 사용하면 노출 family를 regression으로 이동하고 독립 새 family를 채운다는 기존 규칙은 유지한다.

### EP-02 — 범주 최소 표본과 복합 성공 점수를 명확히 고정

‘각 role/split에 가능한 모든 범주’만으로는 어떤 범주를 불가능하다고 빼거나, 속성·거절·혼용 등을 각각 1건만 두고 정확명으로 대부분을 채울 수 있다. docs/21은 각 범주 최소 사례를 기준선 전에 정하도록 요구한다. 열거된 범주와 대응 문서 축(고객 긴 입력/잡음·자모/한영 혼용 포함)을 매핑하고 **role/split별 최소 표본 수**를 확정해야 한다. 여러 축을 가진 case의 중복 집계와 전체 분모는 구별하며 최소치가 120개 경영주/24개 holdout 안에서 가능한지도 생성 전에 검사한다.

또한 ‘명확 고객 후보 포함/선택유도 정확도>=95%’의 슬래시는 판정이 불명확하다. 정답 후보가 목록에 있어도 엉뚱한 상품을 추천·확정하도록 유도하면 정상 성공이 아니다. 후보 Recall@k는 보조 지표로 분리하고 출시95%는 **올바른 후보 제시와 잘못된 확정 유도 없음**의 case별 composite 또는 명확히 정의한 최종 행동 정확도로 고정한다. 모호/미식별 90%와 경영주 scope/조건95%도 case별 필수 필드 모두 충족인지 명시하면 구현 가능하다. 실패를 평균으로 상쇄하지 않는 기존 불변식0/필수여정100은 유지한다.

검증: dataset 생성 시 범주별 최소치·family split 검사, 정답 포함+오답 확정 유도 반례가 정확도 실패로 채점되는 scorer test.

### EP-03 — 편의성 비교의 단위·표본·시간 분리를 사전 고정

7개 ‘의사결정’과 ‘필수조작/화면이동 증가0’는 서로 다른 단위다. 예를 들어 수량+버튼 3회가 한 의사결정인지 세 조작인지, 펼친 고객 상세가 화면 이동인지에 따라 같은 UI도 판정이 바뀐다. 완료시간 중앙값10%의 표본 수도 아직 없어 네트워크/에이전트 대기와 실제 조작 차이를 구분하기 어렵다.
