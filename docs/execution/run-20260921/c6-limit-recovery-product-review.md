# 후보 한도 도달 후 사용자에게 제시할 재개 범위의 제품 검토

상태: **사용자 미승인 제안 검토**. reviewer research, 제안자 root. 코드·평가 기준 변경 및 모델/브라우저/장부 실행0. 이 문서는 추가 후보를 승인하지 않는다.

## 결론

고객 전용 후보를 **한 번만 추가**하여 customer7/merchant6, 총13으로 한정하는 제안이 양 역할7/총14보다 적절하다. 현재 확인된 새 결함은 고객의 미등록 상품·대체 거절을 다른 SKU의 exact로 표시한 회귀이며, 경영주를 다시 수정할 제품 근거는 없다. 기존 상한 도달은 사실이므로 새 사용자 승인 전에는 구현·유료 평가를 시작하지 않는다. API 추정 상한$20과 호출2400의 여유가 추가 후보 권한을 뜻하지 않는다.

## 보존할 실패와 목적

C6 공개 dev 결과29/30, 고객 uncertain6/7=85.71%<90 및 B0/C1~5에서 정상인 사례의 회귀1을 보존한다. 전체96.67%로 역할 기준을 대체하거나 mandatory0만으로 승인할 수 없다. C5 final holdout 미달, C6 validation/new holdout 미실행, 과거 UX48의 실패와 새UX/G5/G6 미실행도 그대로다. 현재 출시 적격 best는 없다.

정확한 상품은 빠르게 찾고 고객이 직접 확인하게 하며, 식별 근거가 없거나 사용자가 대체를 거절했다면 다른 상품을 원상품으로 확정하지 않는 것이 목적이다. 공개 C05 실패는 이 목적에 직접 관련되므로 추가 한 번의 고객 복구 제안에는 제품상 근거가 있다. 하지만 하나의 확률적 실패가 특정 구현 원인의 확정 증거는 아니다.

## 한정 후보의 경계

- 변경은 고객 prompt/schema/고객 전용 해석 분기 중 가설에 필요한 최소 부분으로 제한한다. 특정 case ID·정답·고유 미등록 이름 하드코딩, 출력 후 정답 덮어쓰기, fixture 대체, 모든 미등록 표현의 일괄 거절은 제외한다.
- 고객 정상 정확명/오타·별칭/속성, 모호한 표현의 유용한 질문, 명시 대체 허용과 거절, 후속 정정·실제 후보 history, 질문2회, 미충족 니즈와 수요 구분·동의 경로를 함께 회귀 검증한다. 단순 exact표시 삭제로 잘못된 후보를 confirm에 숨기는 것도 정상 복구가 아니다.
- C6 merchant prompt/schema/입력 packing·모델·catalog/retrieval·도메인 바이트와 동작은 그대로 유지한다. 공유 파일을 편집해야 한다면 고객 분기만 달라짐을 diff/단위/실제 양 역할 평가로 입증한다. 일반 모델·공통 prompt/packing/검색 변경처럼 경영주 동작에도 영향을 주면 customer7/merchant6 승인의 범위를 벗어나므로 별도 변경 권한 없이는 실행하지 않는다.
- 이전 C1~C6 후보 집계는 재해석하거나 초기화하지 않는다. 추가 슬롯은 고객7번째 하나이지 새 6회 묶음이 아니다. 신규 source명을 여러 번 바꾸어 유료 후보를 늘리지 않는다.

## 승인 후에도 유지할 검증과 중단

사용자가 이 범위를 승인하는 경우에만 원래 고정 공개 dev30/34turn 선별→동일 validation84/92turn 두 repeat→최종 source동결→아직 미실행인 새 holdout84/92turn 1회 경로를 제안한다. dev의 최소기준·정상 회귀를 통과하지 못하면 이후 유료 단계로 보내지 않는다. 기존95/90·mandatory0·정상필수100, B0 오류≥2 개선과 C5 대응repeat 핵심범주/필수정상회귀0 조건은 그대로다. C6에서 드러난 공개 실패도 고정 회귀로 남긴다. merchant 수정은 없어도 양 역할의 기존 평가 분모와 검증은 줄이지 않는다.

현재 frozen 새 holdout은 한 번도 실행되지 않았고 구현자에게 원문/정답이 노출되지 않았다는 평가자 확인 하에서 그대로 사용한다. 새 후보를 위해 더 쉬운 세트를 만들지 않는다. 은퇴한 옛 holdout은 재실행하지 않는다. 새 final 결과를 보고 추가 후보/새 holdout/같은 holdout 재시험을 자동 시작하지 않는다.

종료 장부 보고값 upper1098calls/$7.3603041을 기준으로, 기존 미래984attempt/$10.332와 추가 dev최대102attempt/$1.071 및 다음unknown$.05를 예약하면 예시 상한2184calls/$18.8133041이다. 이는 보고 숫자의 산술 검토이며 실장부 확인이나 실행 GO가 아니다. 승인 시점에 실제 잔량·pending·이전unknown/prior50·필수 UX/고객경영주QA/G5/G6 예약을 다시 대조해야 한다. 부족하거나 quota/auth 문제가 나면 호출을 늘리거나 다른 장부로 우회하지 않는다.

추가 후보가 어떤 필수 단계에서든 기준 미달이면 실패와 미실행을 기록하고 자동 추가0으로 종료한다. 통과 시에도 ADR007 고정 UX 양 arm·current 후보 두 역할 독립 실제 QA·G5·main/Production 및 제출URL G6까지 완료해야 한다. 고객전용 한 번의 추가 승인은 이 최종 검증을 생략하거나 품질 기준을 낮추는 승인이 아니다.

## 사용자 제안 표현

“현재 6번째 후보가 고객 미식별 처리에서 회귀해 정해 둔 후보 한도에 도달했습니다. 실패 기록과 품질 기준, $20/2400 한도를 그대로 두고 **경영주 로직을 변경하지 않는 고객 복구 후보 한 번만** 추가할 수 있습니다. 통과하면 남은 최종 평가와 배포 검증을 계속하고, 다시 미달하면 자동 추가 없이 중단합니다.”

조정자가 사용자에게 제시할 수 있는 설명 초안일 뿐, 본 검토자의 채택이나 실행 지시가 아니다.
