# C2 — 상품 카탈로그 전송 축소와 응답 완료 여유

C1 dev30은22PASS/8FAIL이며 기존 정상7건 회귀로 기각했다. 5건은 출력1600 상한에 도달했고 그중3건은 정확한 C1 Vercel 로그에서 `incomplete/max_output_tokens`를 확인했다. 짧은입력2871에서도 발생했으므로 입력량만 원인이라고 단정하지 않는다. validation/holdout으로 후보를 승격하지 않았다.

C2는 복합가설이다: 반복 키를 columns/rows로 바꾸되248개의 이름·브랜드·분류·크기·맛·별칭·관측사실을 그대로 보존하고, 모델에만 안정적인 짧은 참조를 사용한다. 생성 schema에도 해당 참조 enum을 쓰며 서버가 원래 SKU로 복원한 뒤 기존 검증을 그대로 수행한다. 사용자 자유 발화는 재작성하지 않고, 발화에 포함된 원래 SKU는 정확 참조표로 연결한다. 현재/이전 조건·그룹 및 구조화된 assistant history만 ID를 변환한다. 전역 카탈로그 순서에 고정한 map이므로 요청별 검색 순서가 바뀌어도 같은 참조는 같은 상품이다.

출력 한도는1600→3200으로 늘리되45초 timeout·재시도0·사용량 기록·전체 goal2400회/$15 소프트중단을 유지한다. 기존 exact 후보에 미확인 조건이 있으면 안 된다는 규칙을 생성 schema에도 반영한다. 경영주 미결정 모순을 임의의 일부 명령으로 바꾸지 않도록 일반 지시를 보강한다. UI/API/SQLite에 전달되는 SKU와 고객/경영주 확인·동의는 바뀌지 않는다.

독립 설계 검토는 출력만 늘리거나 원래SKU를 유지하는 더 단순한 대안도 제시했다. 조정자는 남은 후보 한도 안에서 입력/schema 비용과 ID 복사를 함께 줄이는 복합 후보를 선택했다. 성공하더라도 어느 한 요소의 단독 효과라고 주장하지 않는다. 전체 payload/token 절감·실제 정확도·지연·비용은 고정30dev와 조건부84validation으로 확인한다. 보호84는 최종best 전 접근하지 않는다.

자체21서버 테스트·typecheck PASS, 독립 기술검토 및 CI 완료 전 실제 모델 호출0. 기존 B0 UX 실패·비교NOT_READY를 새 기준선으로 교체하지 않는다.
