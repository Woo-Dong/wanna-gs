# C6 기술 변경 자체 검증

목적: 고객이 실제 상품을 찾고 명시 동의로 신청하는 정상 흐름, 경영주의 현재/미래 수정·조건 복사·복원·보수적 실행을 유지한다. 특정 SKU 제외를 카테고리 전체로 확장하거나, 실제 카드결제/본부 보고 명령을 검색 성공으로 바꾸는 모델 제안을 생성 단계에서 줄인다. 마지막 후보의 실제 모델 품질을 미리 성공으로 간주하지 않는다.

- 두 역할의 좁은 양성 문법이 입력 전체의 지원 범위를 증명한 경우에만 structured output의 허용 공간을 줄인다. 모호/인용/부정/미인식 표현은 기존 모델 경로로 돌아간다. 출력 후 잘못된 값을 지우거나 fixture로 대체하지 않는다.
- 경영주 완전 상품명/ID·실제 점포명·명시 제외/예산/수량/범위절을 소비한 경우 categories.maxItems=0이다. 별칭·category-only/mixed·명시 기존정책 복사·복원은 기존 schema를 유지하고 stale 제한은 우선한다.
- 고객의 명시 실제 거래/본부 보고 실행은 범위 경계 action 및 빈 후보만 허용한다. count2에서 추가 질문을 금지한다. 정상 검색/비실행 요청·보고된 발화는 제한하지 않는다.
- 최초 고객 자체 테스트에서 정규식 문자열 escape 결함을 찾아 수정했다. 이후 독립 검토에서 앞 문맥의 무시/전달 발화를 실제 명령으로 오인하는 C6-I01을 발견해, 임의 prefix 대신 제한된 literal 문맥과 실행절 전체를 소비하도록 수정했다. 해당 실패·수정·회귀를 독립 보고서에 보존했다.
- 서버 자체41개 및 타입 검사 PASS. builder의 merchant 자체8개가 포함되며 독립 검증으로 세지 않는다. 공개 dev/validation의 오프라인 검사에서 경영주27/72·9/24, 고객7/180·2/60에만 제한이 적용됐다. 제품·평가 원문 하드코딩은 없으며 이 개수는 실제 모델 성공률이 아니다.
- 새 보호 데이터 revision은 기존 manifest를 수정하지 않고 별도 파일/ref/hash로 선택한다. 공개 split 불변·84/92·정확 label 분모·새 family hash·이전 FAIL/재호출금지·독립 정답/난도 검토·데이터 동결 시각·실행 source binding을 검사한다. semantic family의 실질 판단은 해시만으로 증명할 수 없어 별도 독립 데이터 검토가 필수다.
- revision 기구 자체검사에서81개 release 회귀 PASS. 독립 검토의 분모14/10 변조와 bool overlap 허용 결함을 수정하고 재검증했다. 실제 새 데이터는 독립 검토 완료 전 NOT_READY다.

모델/cost/실행기·scorer·catalog/seed·거래/동의·수량/예산·48시간·클라이언트 화면은 변경하지 않았다. promptVersion은 생성 schema 변경과 함께 grounded-boundaries-v6로 구분한다. 실제 후보 평가·두 역할 UX·G5/G6는 별도이며 기존 모든 실패와 작업 공간을 보존한다.
